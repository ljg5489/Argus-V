# Argus-V 모델 전체 정리 — Argus-V-p → Argus-V-em → Argus-V-emp

작성 2026-11-17. 지금까지 만든 모델을 한 문서에 모았다. 모델마다 어떻게 구성했는지, 무엇이 나왔는지, 그 결과를 보고 무엇을 바꿨는지, 왜 마지막에 Argus-V-emp가 됐는지를 표로 적는다.

- 숫자는 각 폴더의 기록에서 옮겼다(위치는 9절). 새 분할의 비교표는 저장된 점수를 같은 방법으로 다시 채점해 자동으로 만든 것이다(`argus-v-emp/overview_tables.md`, 만드는 스크립트는 `experiments/risk_loop/argus_loop/argus_v_overview_table.py`). 이 문서를 쓰면서 새로 학습한 것은 없다.
- AUROC는 0~1이고, 0.5가 우연, 1이 완벽이다. 굵은 글씨는 그 열에서 가장 높은 값이다.

## 1. 한눈에 보기

**결론**: 모델 하나를 고르지 않고 두 계열의 점수를 섞은 **Argus-V-emp**가 마지막 모델이다. 새 분할의 test(위반 26개 대 정상 호출 3,194개)를 도구·시기 구분 없이 전부 비교하면 AUROC **0.913**, 같은 시기의 호출끼리 비교하면 **0.822**, 같은 도구의 호출끼리 비교하면 0.598이다.

| | Argus-V-p | Argus-V-em | **Argus-V-emp** |
|---|---|---|---|
| 한 줄 설명 | 은닉층 값을 PCA로 줄이고, 선형 모델 3개(+랜덤 포레스트)로 점수를 낸다 | 은닉층 값을 줄이는 방법까지 학습하는 작은 신경망 | 위 두 계열의 점수를 섞는다 |
| 만든 때 | 2026-11-15 | 2026-11-15 ~ 11-16 | 2026-11-17 |
| 설정 | 6개 (P1~P6) | 모델 4종(32·64·128차원, 선형 대조) × 위반 가중치 | 1개 |
| 위반으로 학습하는 것 | 위반 전부 | 근거가 보인 위반만 | 학습 없음 (점수만 섞는다) |
| epoch | 없음 (한 번에 푸는 모델) | 있음 (비교는 67 epoch) | 없음 |
| test 위반 26개 · 전부 비교 | 0.624 ~ 0.875 | 0.650 ~ 0.914 | **0.913** |
| test 위반 26개 · 같은 시기끼리 | 0.528 ~ 0.796 | 0.588 ~ 0.774 | **0.822** |
| test 근거가 보인 위반 10개 · 전부 비교 | 0.734 ~ 0.906 | 0.719 ~ 0.921 | **0.962** |
| 정상의 5%에 경보를 낼 때 잡은 위반 (26개 중) | 1 ~ 10 | 7.3 ~ 12.7 | 12 |
| 강점 | 같은 시기 안에서도 위반을 높은 쪽에 둔다 (P3) | 점수 맨 위쪽에 위반을 더 많이 올린다 | 두 강점이 합쳐진다 |
| 약점 | 엄격한 문턱에서 거의 못 잡는 설정이 있다 (P3: 26개 중 1개) | 학습할 때마다 결과가 흔들린다 (같은 설정이 0.67 ~ 0.84) | 같은 도구 안에서 가르는 능력은 오르지 않았다 |

표의 범위는 그 계열의 모든 설정 가운데 가장 낮은 값 ~ 가장 높은 값이다(새 분할, 6절의 표).

### 2-3. 점수를 채점하는 방법

모델은 어떤 방법으로 채점하든 같은 점수를 낸다. 아래는 그 점수를 무엇끼리 비교하느냐의 차이다.

| 채점 방법 | 무엇끼리 비교하나 | 무엇을 알려 주나 | 모델 없이 나오는 값 |
|---|---|---|---|
| 도구·시기 구분 없이 전부 비교 | 위반 전부 대 정상 호출 전부 | 실제로 쓸 때에 가장 가까운 값 | "10월 기록이면 높게"만 해도 test 0.750 (근거가 보인 위반은 0.861) |
| 같은 시기의 호출끼리 비교 | 10월 기록끼리, 11월 기록끼리 따로 비교해 합친다 | 기록 시기 덕을 뺀 값 | 0.5 |
| 같은 도구의 호출끼리 비교 | 같은 도구를 쓴 위반과 정상 호출끼리만 | "어떤 도구인가"로 맞히는 몫까지 뺀 값. 처음 세운 목표(0.90)의 기준이다 | 0.5 안팎 |

| 용어 | 뜻 |
|---|---|
| 기록 시기 | 실행 기록을 모은 때. 10월에 모은 기록은 호출의 약 5.7%가 위반이고 11월에 모은 기록은 0.4%다. 그래서 "10월 기록처럼 보이는 호출"에 점수를 높게 주기만 해도 전부 비교 값이 0.75가 된다 |
| 근거가 보인 위반 | 행동하기 전에 모델이 본 내용만으로 위반임을 알 수 있었던 위반. 기록에서 규칙으로 표시했다(잠정 규칙): bash로 한 행동, 승인 번호가 없거나 받은 적 없는 번호로 한 행동, 앞에서 거절·불가 응답을 받은 뒤에 한 행동은 "보임". 받은 승인 번호를 범위 밖에 쓴 것, 기록에 드러나지 않은 조건에 걸린 것, 입력 형식 오류는 "보이지 않음" |
| 5% 문턱 | validation 정상 호출의 5%가 경보가 되는 점수. 이 문턱을 test에 그대로 적용해 잡은 위반 수를 센다 |
| train 재채점 | 학습에 쓴 데이터를 그 모델로 다시 채점한 값. 외운 정도를 보여 줄 뿐 성능이 아니다 |

## 4. Argus-V-p — PCA와 선형 모델

### 4-1. 구조 (6개 설정에 공통인 뼈대)

| 순서 | 내용 |
|---|---|
| 1 | 입력 5,760개의 척도를 맞추고 ±3에서 자른다 |
| 2 | PCA로 줄인다 (층 23은 32차원, 층 16은 10차원) |
| 3 | 선형 모델 3개를 학습한다. ① 층 23 값으로 호출 하나하나를 위반 / 정상으로 가르는 로지스틱 회귀 ② 층 23 값으로 "같은 실행 안에서 위반 호출이 정상 호출보다 높게" 순서를 맞히는 모델 ③ 층 16 값으로 ②와 같은 일을 하는 모델 |
| 4 | 세 모델의 점수를 각각 학습 데이터 안의 백분위로 바꿔 평균한다 |

### 4-2. 설정 6개 — 무엇을 바꿨고 왜 해 봤나

| 설정 | 바꾼 것 | 해 본 이유 | PCA 차원 (①·②·③) | 규제 | 랜덤 포레스트 |
|---|---|---|---|---|---|
| P1 | 없음 (그때까지 가장 좋았던 모델 그대로) | 기준 | 32 · 32 · 10 | 그대로 | 없음 |
| P2 | 같은 도구 안에서만 배우게 함: 도구×시기 칸의 평균을 빼고, 같은 칸의 위반·정상 쌍으로 학습 | 도구 이름으로 맞히는 몫을 없애려고 | 32 · 32 · 10 | 그대로 | 없음 |
| P3 | 규제 완화 | 더 많은 신호를 담게 하려고 | 128 · 128 · 32 | 벌점 1/10 | 없음 |
| P4 | P2 + P3 | 둘을 함께 | 128 · 128 · 32 | 벌점 1/10 | 없음 |
| P5 | P1 + 랜덤 포레스트 | 선형 모델이 못 잡는 모양을 잡으려고 | 32 · 32 · 10 | 그대로 | 넷째 구성원, 비중 1/4, 나무 500개 |
| P6 | P2 + P3 + 랜덤 포레스트 | 전부 함께 | 128 · 128 · 32 | 벌점 1/10 | 위와 같음 |

### 4-3. 기존 분할의 결과 (2026-11-15)

같은 도구의 호출끼리 비교한 AUROC, 위반 48개. 세 열 모두 train 안의 값이다.

| 설정 | train 데이터만으로 한 5-fold 교차검증 | 같은 시나리오의 다른 실행을 채점 | train 재채점 |
|---|---|---|---|
| P1 | **0.714** | 0.682 | 0.815 |
| P2 | 0.657 | 0.632 | 0.826 |
| P3 | 0.468 | 0.566 | 0.847 |
| P4 | 0.565 | 0.635 | 0.964 |
| P5 | 0.701 | **0.687** | 0.869 |
| P6 | 0.571 | 0.627 | **0.979** |

| 기존 test를 한 번 채점한 값 (P5만 채점) | 값 | 쓰인 위반 |
|---|---|---|
| 같은 도구끼리 비교 | 0.644 | 9개 |
| 같은 도구끼리, 근거가 보인 위반만 | 0.600 | 3개 |
| 도구·시기 구분 없이 전부 비교 | 0.835 | 24개 ("10월이면 높게" 규칙은 0.773) |

읽기: 규제를 풀거나(P3·P4·P6) 같은 도구 안에서만 배우게 하면(P2) train 재채점만 오르고 교차검증은 내려갔다. 미리 정한 규칙(둘째 열이 가장 높은 설정)으로 그때의 Argus-V-p는 P5였다.

- P5는 전부 비교가 가장 높고(test 0.875) 5% 문턱에서 가장 많이 잡는다(26개 중 10개).
- 같은 도구 안에서만 배우게 한 설정(P2·P4·P6)은 새 분할에서도 전부 비교와 같은 시기끼리 비교가 모두 낮고, 같은 도구끼리 비교해도 더 높지 않다(test 0.58 대 0.60 ~ 0.62).
- 기존 분할의 교차검증에서 가장 낮았던 P3가 새 분할에서는 위쪽이다. 설정의 순위가 데이터와 채점 방법에 따라 바뀐다.

## 5. Argus-V-em — 학습하는 임베딩

### 5-1. 구조

| 순서 | 내용 |
|---|---|
| 1 | 입력 5,760개의 척도를 맞추고 자른다 |
| 2 | 선형 층 5,760 → 32 / 64 / 128 (이 층이 "학습하는 임베딩"이다. PCA를 대신한다) |
| 3 | LayerNorm → GELU → Dropout 0.15 |
| 4 | 선형 층 → 점수 1개 |

| 모델 | 임베딩 크기 | 학습되는 값의 수 | 역할 |
|---|---|---|---|
| 32차원 | 32 | 184,449 | |
| 64차원 | 64 | 368,897 | |
| 128차원 | 128 | 737,793 | |
| 선형 대조 | 없음 (5,760 → 점수 1개) | 5,761 | 임베딩이 정말 필요한지 보려는 비교 대상 |

### 5-2. 학습 방법

| 항목 | 값 |
|---|---|
| 위반으로 학습하는 것 | 근거가 보인 위반만 (기존 train 22개, 새 train 26개). 근거가 보이지 않은 위반은 학습에서 뺀다 |
| 정상 호출 | 도구×시기 칸마다 max(30, 20 × 그 칸의 근거가 보인 위반 수)개까지 뽑는다 (새 train 5,334개) |
| 손실 | 이진 교차 엔트로피. 위반 1개를 정상 호출 여러 개만큼 무겁게 친다(위반 가중치, 5-4절) |
| 최적화 | AdamW, 학습률 0.001, weight decay 0.01. 전체 행을 한꺼번에 넣으므로 1 epoch이 가중치를 한 번 고치는 것이다 |
| epoch | 처음 60 → 300까지 늘림 → 가중치 실험과 새 분할은 100 |
| 비교하는 epoch | 67. 기존 분할의 교차검증에서 가장 높았던 곳(64차원, 0.968)이고, 새 분할에서는 학습 전에 고정했다 |

## 7. Argus-V-emp — 두 계열을 섞은 모델

### 7-1. 왜 섞었나

값은 test의 위반 26개를 전부 비교한 AUROC이고 괄호 안은 validation이다.

| 본 것 | 숫자 | 뜻 |
|---|---|---|
| 같은 설정도 학습할 때마다 달라진다 | 64차원·약 60배의 반복 3번이 0.67 ~ 0.84 | 모델 하나의 숫자는 믿기 어렵다 |
| 같은 설정의 반복 3번을 평균 | 0.767 → 0.781 (0.680 → 0.682) | 조금 오른다 |
| Argus-V-em 12개 설정을 모두 평균 | 0.767 → 0.840 (0.680 → 0.728) | 더 오른다 |
| Argus-V-p는 잘하는 곳이 다르다 | P3는 같은 시기끼리 0.796인데 5% 문턱에서 1개만 잡는다. Argus-V-em은 같은 시기끼리 0.59 ~ 0.77인데 7 ~ 13개를 잡는다 | 두 계열이 서로 다른 실수를 한다 |
| 두 계열을 섞음 | 0.840 → 0.913 (0.728 → 0.837) | 가장 높다. 이것을 택했다 |
| 점수를 도구별·시기별·실행별로 보정 | 0.51 ~ 0.67 (0.44 ~ 0.57) | 내려간다. 버렸다 |
