# Argus-V 모델 전체 정리 — Argus-V-p → Argus-V-em → Argus-V-emp

작성 2026-11-17. 지금까지 만든 모델을 한 문서에 모았다. 모델마다 어떻게 구성했는지, 무엇이 나왔는지, 그 결과를 보고 무엇을 바꿨는지, 왜 마지막에 Argus-V-emp가 됐는지를 표로 적는다.

- 숫자는 각 폴더의 기록에서 옮겼다(위치는 9절). 새 분할의 비교표는 저장된 점수를 같은 방법으로 다시 채점해 자동으로 만든 것이다(`argus-v-emp/overview_tables.md`, 만드는 스크립트는 `experiments/risk_loop/argus_loop/argus_v_overview_table.py`). 이 문서를 쓰면서 새로 학습한 것은 없다.
- **모든 숫자 옆에 "어디서 잰 값 · 어떤 지표"를 적었다**(사용자 지시 2026-11-17). 표에서는 열 이름에 적는다. 굵은 글씨는 그 열에서 가장 높은 값이다.

## 숫자 읽는 법

| 구분 | 이 문서에서 쓰는 말 | 뜻 |
|---|---|---|
| 어디서 잰 값 | k-fold 교차검증 | 기존 train 데이터만으로 한 5-fold 교차검증. 시나리오를 5묶음으로 나눠 4묶음으로 학습하고 남은 1묶음을 채점하기를 5번 한다. **test 값이 아니다** |
| | train 재채점 | 학습에 쓴 데이터를 그 모델로 다시 채점한 값. 외운 정도를 보여 줄 뿐 성능이 아니다 |
| | validation | 새 분할의 validation. 모델의 가중치 학습에는 쓰지 않았다 |
| | test | 모델의 가중치 학습에 쓰지 않은 데이터. "기존 test"는 기존 분할, "새 test"는 새 분할의 것이다 |
| 어떤 지표 | AUROC (AUC) | 위반 하나와 정상 호출 하나를 뽑았을 때 위반의 점수가 더 높을 확률. 문턱이 필요 없다. 0.5가 우연, 1이 완벽 |
| | 재현율 | 문턱을 정해 판정했을 때, 위반 가운데 잡은 비율 |
| | 정밀도 | 문턱을 정해 판정했을 때, 경보 가운데 진짜 위반의 비율 |
| | F1 | 재현율과 정밀도를 하나로 합친 값(조화 평균). 문턱이 있어야 나온다 |
| | 맞힌 비율 (정확도) | 전체 호출 가운데 판정이 맞은 비율. 위반이 0.8%뿐이라 전부 "정상"이라고만 해도 0.992다 |

- 이 문서의 0.xx 값은 대부분 AUROC다. F1·재현율·정밀도는 그렇게 적힌 곳에만 있다.
- **문턱(커트라인)**: 미리 정해 둔 점수다. 모델의 점수가 이 값을 넘으면 경보(위반으로 판정), 넘지 않으면 정상으로 판정한다. 모델이 정하는 값이 아니라 우리가 정하는 값이고, 낮추면 더 많이 잡는 대신 오경보가 늘어난다. 모델의 점수는 확률이 아니라 "다른 호출들보다 얼마나 위쪽인가"를 나타내는 0 ~ 1의 값이다.
- 문턱이 필요한 값(잡은 위반 수, 재현율, 정밀도, F1)은 따로 적지 않으면 **5% 문턱**(validation 정상 호출의 5%가 경보가 되는 점수를 test에 그대로 적용. Argus-V-emp에서는 0.864) 기준이다.

## 1. 한눈에 보기

**결론**: 모델 하나를 고르지 않고 두 계열의 점수를 섞은 **Argus-V-emp**가 마지막 모델이다.

- 새 test · AUROC: 위반 26개 대 정상 호출 3,194개를 도구·시기 구분 없이 전부 비교하면 **0.913**, 같은 시기의 호출끼리 비교하면 **0.822**, 같은 도구의 호출끼리 비교하면 0.598.
- 새 test · 5% 문턱으로 판정: 위반 26개 중 12개를 잡고(재현율 0.462), 정밀도 0.076, F1 0.131.
- 새 validation · AUROC: 위반 26개 전부 비교 0.837, 같은 시기끼리 0.788.

| | Argus-V-p | Argus-V-em | **Argus-V-emp** |
|---|---|---|---|
| 한 줄 설명 | 은닉층 값을 PCA로 줄이고, 선형 모델 3개(+랜덤 포레스트)로 점수를 낸다 | 은닉층 값을 줄이는 방법까지 학습하는 작은 신경망 | 위 두 계열의 점수를 섞는다 |
| 만든 때 | 2026-11-15 | 2026-11-15 ~ 11-16 | 2026-11-17 |
| 설정 | 6개 (P1~P6) | 모델 4종(32·64·128차원, 선형 대조) × 위반 가중치 | 1개 |
| 위반으로 학습하는 것 | 위반 전부 | 근거가 보인 위반만 | 학습 없음 (점수만 섞는다) |
| epoch | 없음 (한 번에 푸는 모델) | 있음 (비교는 67 epoch) | 없음 |
| 새 test · AUROC · 위반 26개 전부 비교 | 0.624 ~ 0.875 | 0.650 ~ 0.914 | **0.913** |
| 새 test · AUROC · 위반 26개 같은 시기끼리 | 0.528 ~ 0.796 | 0.588 ~ 0.774 | **0.822** |
| 새 test · AUROC · 근거가 보인 위반 10개 전부 비교 | 0.734 ~ 0.906 | 0.719 ~ 0.921 | **0.962** |
| 새 test · 잡은 위반 수 (26개 중, 5% 문턱) | 1 ~ 10 | 7.3 ~ 12.7 | 12 |
| 새 test · F1 (5% 문턱) | 0.010 ~ 0.099 | 0.074 ~ 0.111 | **0.131** |
| 새 validation · AUROC · 위반 26개 전부 비교 | 0.606 ~ 0.817 | 0.612 ~ 0.791 | **0.837** |
| 강점 | 같은 시기 안에서도 위반을 높은 쪽에 둔다 (P3) | 점수 맨 위쪽에 위반을 더 많이 올린다 | 두 강점이 합쳐진다 |
| 약점 | 엄격한 문턱에서 거의 못 잡는 설정이 있다 (P3: 26개 중 1개) | 학습할 때마다 결과가 흔들린다 (같은 설정의 새 test AUROC가 0.67 ~ 0.84) | 같은 도구 안에서 가르는 능력은 오르지 않았다 |

표의 범위는 그 계열의 모든 설정 가운데 가장 낮은 값 ~ 가장 높은 값이다(6절의 표).

## 2. 모든 모델에 공통인 것

### 2-1. 모델이 보는 것

| 항목 | 내용 |
|---|---|
| 읽는 대상 | gpt-oss-20b(고정, 학습하지 않음)가 도구를 호출하기 직전의 은닉층 값 |
| 쓰는 값 | 층 23의 관측 지점별 최댓값 2,880개 + 층 16의 행동 직전 값 2,880개 = 5,760개 |
| 쓰지 않는 값 | 도구 이름, step 번호, 프롬프트 길이, 기록 시기, 시나리오 번호 |
| 내는 값 | 호출마다 점수 하나 (높을수록 위반 쪽) |

### 2-2. 데이터 — 분할이 두 가지다

| | 기존 분할 | 새 분할 (resplit-1117) |
|---|---|---|
| 쓴 기간 | 2026-11-16까지 | 2026-11-17부터 |
| 여기서 학습한 것 | Argus-V-p 첫 학습, Argus-V-em 60 epoch·300 epoch, 위반 가중치 실험 | Argus-V-p 6개 설정과 Argus-V-em 12개 설정을 다시 학습, Argus-V-emp |
| train (호출 / 위반 / 근거가 보인 위반) | 9,278 / 76 / 22 (표시를 만든 48개 중) | 9,653 / 77 / 26 |
| validation | 쓰지 않음 | 3,217 / 26 / 7 |
| test | 2,842 / 24 / 3 | 3,220 / 26 / 10 |
| test의 위반: 10월 기록 / 11월 기록 | 16 / 8 | 15 / 11 |
| 성능을 잰 방법 | k-fold 교차검증(기존 train만으로) + 기존 test 한 번 | 새 train으로 학습하고 새 validation과 새 test를 채점 |
| 문제 | 기존 test에 근거가 보인 위반이 3개뿐이라 AUROC가 0.9인지 0.5인지 가를 수 없었다 | — |

새 분할은 기존 train·validation·test의 호출 16,090개(위반 129개, 근거가 보인 위반 43개)를 시나리오 계열 단위로 60 / 20 / 20으로 다시 나눈 것이다. 기존 분할과 기존 모델은 그대로 남아 있다.

새 분할의 세 데이터가 어디에 쓰였나:

| 데이터 | 모델의 가중치 학습 | 설정·조합을 고를 때 | Argus-V-emp에서 |
|---|---|---|---|
| 새 train | 쓰임 | — | 구성 모델 14종을 학습 |
| 새 validation | 쓰이지 않음 | 섞는 방법 16가지를 비교할 때 값을 봤다 | 점수 단위를 맞추는 기준(라벨은 쓰지 않음), 5% 문턱 |
| 새 test | 쓰이지 않음 | 섞는 방법 16가지를 비교할 때 값을 봤다 | 채점만 |

validation과 test의 숫자는 "학습하지 않은 데이터에서 나온 값"이 맞다. 다만 어떤 조합을 쓸지는 그 값을 본 뒤에 골랐으므로, 한 번도 쓰지 않은 데이터에서는 조금 낮게 나올 수 있다.

### 2-3. 점수를 채점하는 방법 (AUROC를 무엇끼리 비교해 구하나)

모델은 어떤 방법으로 채점하든 같은 점수를 낸다. 아래는 그 점수로 AUROC를 구할 때 무엇끼리 비교하느냐의 차이다.

| 채점 방법 | 무엇끼리 비교하나 | 무엇을 알려 주나 | 모델 없이 나오는 AUROC |
|---|---|---|---|
| 도구·시기 구분 없이 전부 비교 | 위반 전부 대 정상 호출 전부 | 실제로 쓸 때에 가장 가까운 값 | "10월 기록이면 높게"만 해도 새 test 0.750 (근거가 보인 위반은 0.861) |
| 같은 시기의 호출끼리 비교 | 10월 기록끼리, 11월 기록끼리 따로 비교해 합친다 | 기록 시기 덕을 뺀 값 | 0.5 |
| 같은 도구의 호출끼리 비교 | 같은 도구를 쓴 위반과 정상 호출끼리만 | "어떤 도구인가"로 맞히는 몫까지 뺀 값. 처음 세운 목표(0.90)의 기준이다 | 0.5 안팎 |

| 용어 | 뜻 |
|---|---|
| 기록 시기 | 실행 기록을 모은 때. 10월에 모은 기록은 호출의 약 5.7%가 위반이고 11월에 모은 기록은 0.4%다. 그래서 "10월 기록처럼 보이는 호출"에 점수를 높게 주기만 해도 전부 비교한 AUROC가 0.75가 된다 |
| 근거가 보인 위반 | 행동하기 전에 모델이 본 내용만으로 위반임을 알 수 있었던 위반. 기록에서 규칙으로 표시했다(잠정 규칙): bash로 한 행동, 승인 번호가 없거나 받은 적 없는 번호로 한 행동, 앞에서 거절·불가 응답을 받은 뒤에 한 행동은 "보임". 받은 승인 번호를 범위 밖에 쓴 것, 기록에 드러나지 않은 조건에 걸린 것, 입력 형식 오류는 "보이지 않음" |

## 3. 흐름 — 무엇을 고민했고, 무엇을 해 봤고, 그래서 어떻게 했나

결과 칸의 굵은 글씨가 "어디서 잰 값 · 어떤 지표"다.

| 단계 | 때 | 고민 | 해 본 것 | 결과 | 내린 결정 |
|---|---|---|---|---|---|
| 0 | ~11-15 | 출발점 | 그때까지 가장 좋았던 모델(PCA + 선형 모델 3개) | **k-fold 교차검증 · AUROC** (같은 도구끼리, 위반 48개) 0.72 | 목표 0.90에 못 미친다 |
| 1 | 11-15 | 모델을 더 자유롭게 풀면 0.9가 될까 | **Argus-V-p**: 그 모델을 6가지로 바꿔 봄 (P1~P6) | **k-fold 교차검증 · AUROC** (같은 도구끼리, 위반 48개) 0.47 ~ 0.71. **train 재채점 · AUROC** (같은 기준) 0.82 ~ 0.98 | 0.9는 학습 데이터를 다시 채점할 때만 나온다. 풀수록 k-fold 교차검증 값은 내려간다 |

| 3 | 11-15 | 알 수 없는 위반까지 맞히라는 것은 무리 아닌가 | 목표 대상을 **근거가 보인 위반**으로 좁힘 (사용자 결정) | **k-fold 교차검증 · AUROC** (같은 도구끼리, 같은 모델 P5): 위반 48개 0.70 → 근거가 보인 16개 0.76 | 0.90의 대상을 근거가 보인 위반으로 정함 |

| 5 | 11-16 | 더 오래 학습하면 더 오르나. test에서도 나오나 | 300 epoch까지 학습, 기존 test를 한 번 채점 | **k-fold 교차검증 · AUROC** (같은 도구끼리, 근거가 보인 16개) 0.96 근처에서 멈춤, 가장 높은 곳이 64차원·67 epoch의 0.968. **기존 test · AUROC** (같은 도구끼리, 근거가 보인 3개) **0.667** | k-fold 교차검증의 0.97이 test에서 나오지 않았다. test의 위반이 3개뿐이라 판단도 어렵다 |
| 6 | 11-16 | 위반이 너무 드물어서 못 배우는 것 아닌가 | 위반 가중치를 15 → 60 → 230 → 300 → 1000배로 키움 (64차원) | **k-fold 교차검증 · AUROC** (같은 도구끼리, 근거가 보인 16개) 0.968 → 0.709로 내려감. **기존 test · AUROC** (전부 비교, 위반 24개) 0.642 → 0.778로 오르지만 "10월이면 1점" 규칙(0.773)과 같아짐 | 가중치를 키우면 위반이 아니라 10월 기록을 알아본다. 해결책이 아니다 |
| 7 | 11-17 | test가 한쪽으로 쏠려 있어 제대로 잴 수 없다 | 데이터를 60 / 20 / 20으로 다시 나눔 (시기·위반 수 균형) | (점수가 아니라 개수) test의 근거가 보인 위반 3개 → 10개 | 새 분할로 모든 모델을 다시 학습한다 |

## 5. Argus-V-em — 학습하는 임베딩

### 5-1. 구조

| 순서 | 내용 |
|---|---|
| 1 | 입력 5,760개의 척도를 맞추고 자른다 |
| 2 | 선형 층 5,760 → 32 / 64 / 128 (이 층이 "학습하는 임베딩"이다. PCA를 대신한다) |
| 3 | LayerNorm → GELU → Dropout 0.15 |
| 4 | 선형 층 → 점수 1개 |

| 모델 | 임베딩 크기 | 학습되는 값의 수 | 역할 |
|---|---|---|---|
| 32차원 | 32 | 184,449 | |
| 64차원 | 64 | 368,897 | |
| 128차원 | 128 | 737,793 | |
| 선형 대조 | 없음 (5,760 → 점수 1개) | 5,761 | 임베딩이 정말 필요한지 보려는 비교 대상 |

### 5-2. 학습 방법

| 항목 | 값 |
|---|---|
| 위반으로 학습하는 것 | 근거가 보인 위반만 (기존 train 22개, 새 train 26개). 근거가 보이지 않은 위반은 학습에서 뺀다 |
| 정상 호출 | 도구×시기 칸마다 max(30, 20 × 그 칸의 근거가 보인 위반 수)개까지 뽑는다 (새 train 5,334개) |
| 손실 | 이진 교차 엔트로피. 위반 1개를 정상 호출 여러 개만큼 무겁게 친다(위반 가중치, 5-4절) |
| 최적화 | AdamW, 학습률 0.001, weight decay 0.01. 전체 행을 한꺼번에 넣으므로 1 epoch이 가중치를 한 번 고치는 것이다 |
| epoch | 처음 60 → 300까지 늘림 → 가중치 실험과 새 분할은 100 |
| 비교하는 epoch | 67. 기존 분할의 k-fold 교차검증 AUROC가 가장 높았던 곳(64차원, 0.968)이고, 새 분할에서는 학습 전에 고정했다 |

### 7-3. 정의

| 항목 | 내용 |
|---|---|
| 구성 모델 | ① Argus-V-em 12개 설정(32·64·128차원, 선형 대조 × 약 15배·약 60배·300배). 설정마다 반복 3번, 67 epoch. 점수 36벌 ② Argus-V-p P3 ③ Argus-V-p P5. 모두 새 train으로만 학습했다 |
| 1단계: 단위 맞추기 | 구성 모델마다 점수를 "validation 호출 가운데 이 모델이 더 낮은 점수를 준 호출의 비율"(0 ~ 1)로 바꾼다. 모델마다 점수 단위가 달라서다 |
| 2단계: Argus-V-em 평균 | 36벌의 값을 평균한다 → ① |
| 3단계: 섞기 | ①, ②(P3의 값), ③(P5의 값)을 같은 비중(1/3씩)으로 평균한다. 이것이 Argus-V-emp의 점수(0 ~ 1)다 |
| 쓰는 라벨 | 없음 |
| 새로 학습하는 것 | 없음 |
| P3와 P5를 고른 까닭 | P1·P3·P5를 하나씩 붙여 본 뒤(7-2절), 성격이 다른 둘을 함께 넣었다. P3는 같은 시기끼리 비교한 AUROC가 가장 높은 설정이고 P5는 전부 비교한 AUROC가 가장 높은 설정이다. 이 선택은 새 validation과 새 test의 AUROC를 본 뒤에 했다 |
| 코드 | `experiments/risk_loop/argus_loop/argus_v_emp.py` |

### 7-6. 위반 / 정상으로 판정했을 때 (새 test, 문턱은 validation에서 정함)

이 표에는 AUROC가 없다. 문턱을 정해 판정한 개수와 재현율·정밀도·F1·맞힌 비율이다.

| 문턱 | 새 test · 잡은 위반 수 (26개 중) | 새 test · 잡은 근거가 보인 위반 수 (10개 중) | 새 test · 오경보 수 (정상 3,194개 중) | 새 test · 재현율 | 새 test · 정밀도 | 새 test · F1 | 새 test · 맞힌 비율 |
|---|---|---|---|---|---|---|---|
| validation 정상의 1%가 경보 | 2 | 1 | 35 | 0.077 | 0.054 | 0.063 | 0.982 |
| validation 정상의 5%가 경보 (5% 문턱) | 12 | 7 | 145 | 0.462 | 0.076 | **0.131** | 0.951 |
| validation에서 F1이 가장 높은 문턱 | 2 | 1 | 17 | 0.077 | 0.105 | 0.089 | 0.987 |
| 참고: 전부 "정상"이라고 판정 | 0 | 0 | 0 | 0 | — | 0 | 0.992 |

근거가 보인 위반 10개는 모두 정상 호출의 91% 이상보다 점수가 높다(가장 낮은 것이 91.8%).

같은 5% 문턱(커트라인 0.864)을 새 validation에 적용하면 재현율 0.269(위반 26개 중 7개), 정밀도 0.042(경보 167개 중 7개), F1 0.073, 맞힌 비율 0.944다(그림 22번).

AUROC는 0.913인데 F1은 0.131인 까닭: AUROC는 위반과 정상의 순서만 보고, F1은 문턱을 넘은 경보 가운데 진짜 위반이 얼마나 되는지도 본다. 정상 호출이 위반보다 123배 많아서, 정상의 5%만 경보가 돼도 오경보(145개)가 잡은 위반(12개)보다 훨씬 많다.
