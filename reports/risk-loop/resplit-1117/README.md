# 새 분할 (resplit-1117) — 2026-11-17

## 왜 만들었나

사용자 지시: "데이터셋부터 다시 train, validation, test 제대로 나누고 시작해 이번에 나눈 것은 지금까지 모델 학습시킨 것에는 영향을 미치지 않게 하고 그래야 기존에 k-fold에서 점수 잘 나온 것으로 안될 경우 시연하지 train데이터를 가지고".

기존 분할은 위반이 한쪽에 몰려 있었다. 예: 기존 test는 10월 기록의 위반 16개·11월 기록의 위반 8개가 시나리오 6개에 있고, 같은 도구끼리 채점할 수 있는 도구가 시기마다 1개였다. 기존 validation은 10월 위반이 3개뿐이고, 기존 train은 10월 위반이 55개였다.

## 기존 것은 그대로다

- 기존 분할 파일(`Scenario/scenario-splits.v1.json`, `.v2.json`), 기존 특징 캐시(`artifacts/risk-loop/argus-v1-loop/`, `argus-v1-loop-test/`), 지금까지 학습한 모델(Argus-V-p, Argus-V-em, Argus-V-em300, 가중치 실험)과 그 결과는 읽기만 했고 바꾸지 않았다.
- 새 분할은 이 폴더와 `artifacts/risk-loop/resplit-1117/`에만 있다. 기존 코드는 새 분할을 읽지 않는다.
- 그래서 기존 모델과 기존 train 데이터로 하는 시연은 전과 똑같이 할 수 있다.

## 어떻게 나눴나

- **대상**: 기존 train·validation·test의 채점 대상 호출 16,090개(위반 129개, 시나리오 계열 71개, 시나리오 176개). 걸러내는 규칙은 지금까지의 평가와 같다(라벨 있음, 보고용 도구 제외, 특징 완전). 봉인 단위(AV-S61~S80)는 넣지 않았다.
- **단위**: 시나리오 계열. 한 계열의 실행은 모두 같은 분할에 들어간다. 같은 시나리오가 두 분할에 걸치지 않는다.
- **비율**: train 60 / validation 20 / test 20.
- **맞춘 것**: 기록 시기(10월·11월)별로 호출 수, 위반 수, 근거가 보인 위반 수, 채점할 수 있는 도구 수가 세 분할에 같은 비율로 들어가게 계열을 배정했다. 라벨과 메타데이터만 썼고 모델 점수는 쓰지 않았다(seed 20261117, 무작위 시작 200번의 지역 탐색, `experiments/risk_loop/argus_loop/resplit.py`).
- **근거가 보였는지 표시**: 위반 129개 전부에 기존 규칙(provisional-1)을 적용했다. 기존에 저장된 표시(train 48개, test 9개)는 그대로 재현된다. 129개 중 43개가 "근거가 보인 위반"이다.

구성 표는 `composition.md`, 계열별 배정은 `families.csv`, 시나리오별 배정과 전체 수치는 `split.json`, 위반별 표시는 `visible_flags.json`.

## 분할로 해결되지 않는 것

1. **10월 기록의 위반 비율이 11월의 약 15배인 것은 데이터 자체의 성질이다.** 새 분할은 세 분할이 그 비율을 똑같이 갖게 했을 뿐이고(5.6~5.7% 대 0.4%), 차이를 없애지는 못한다. "10월 기록이면 경보"만 해도 "모든 호출" 점수가 높게 나오는 문제는 새 분할에서도 그대로다.
2. **주 지표를 낼 수 있는 도구가 데이터 전체에 5개뿐이다**(근거가 보인 위반 3개 이상·정상 3개 이상). 그래서 3 / 1 / 1로 나뉘었다. validation의 주 지표는 위반 3개(비교 9쌍), test는 위반 4개(비교 24쌍)에 기대게 된다.
3. **새 test에는 기존 train에 있던 계열 7개가 들어 있다.** 새 모델은 새 train으로만 학습하므로 가중치는 그 데이터를 본 적이 없다. 다만 모델 구조·근거 표시 규칙·epoch 같은 설계는 기존 train을 보며 정한 것이다.
