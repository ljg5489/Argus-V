# 새 분할 1차 학습 — 결과 (2026-11-17)

계획과 읽는 법은 `README.md`(학습 전에 고정), 분할은 `../README.md`. 모든 모델은 새 train으로만 학습했고 validation·test는 채점만 했다. 숫자 전체는 `tables.md`(자동 생성), `results.json`, `epoch_table.csv`.

용어: **주 지표** = 같은 도구를 쓴 호출끼리 위반과 정상을 비교, 근거가 보인 위반이 3개 이상인 도구만. **넓힌 지표** = 같은 방식, 2개 이상인 도구. **같은 시기 안** = 10월 기록끼리·11월 기록끼리 모든 호출을 정상 대 위반으로 가른 값(위반 수로 가중 평균). 도구 이름과 기록 시기는 모델 입력이 아니다. Argus-V-em 값은 반복 3번의 평균이다.

## 결론

1. **새 분할의 test에서 0.90에 닿은 모델은 없다.**
   - 정해 둔 레시피(Argus-V-em 64차원, 위반 가중치 약 15배, 67 epoch. 아무것도 고르지 않은 값): test 주 지표 **0.833**(비교 24쌍 중 20쌍. 반복별 0.75 / 0.75 / 1.00, 95% 구간 0.50~0.91).
   - 미리 정한 규칙으로 validation에서 고른 모델(Argus-V-p P6): test 주 지표 **0.708**(95% 구간 0.58~0.85).
2. **기존 분할의 test(0.667, 위반 3개)보다는 높게 나왔지만 단정할 수 없다.** 새 test의 주 지표도 위반 4개(도구 1개)로 잰 값이고 구간이 넓다.
3. **위반 가중치는 300배가 가장 낮다.** 67 epoch의 test 주 지표가 약 15배 0.79~0.83, 약 60배 0.63~0.92, 300배 0.50~0.71이다. 약 15배와 약 60배는 구분되지 않는다.
4. **validation에서 좋았던 설정이 test에서 좋지 않다.** 예: 선형 대조는 validation 주 지표가 1.00인데 test는 0.50~0.79다. validation의 위반 3~5개로는 모델이나 epoch을 고를 수 없다.
5. **같은 시기 안에서 모든 호출을 가르는 값**은 test에서 Argus-V-em 0.59~0.78, Argus-V-p 0.53~0.80이다. 기록 시기만 아는 점수는 세 분할 모두 0.75다(시기를 섞어 잴 때의 값).

## 무엇을 했나

- 학습: Argus-V-em 36번(모델 4개 × 위반 가중치 3가지 × 반복 3번, 각 100 epoch), Argus-V-p 6번(P1~P6). 2026-11-17 00:31~00:57, 노트북 CPU. Argus-V-em 한 번에 5~60초, Argus-V-p 전체 52초.
- 학습 대상 행: Argus-V-em은 새 train의 정상 호출 표본 5,334개 + 근거가 보인 위반 26개. Argus-V-p는 새 train의 채점 호출 9,653개 전부(위반 77개).
- 실제로 쓴 위반 가중치: 약 15배 = 14.32, 약 60배 = 54.21, 300배 = 300.
- **중간에 찾은 버그**: 처음 실행(00:31~00:47)에서 스크립트 잘못으로 "약 15배" 설정의 반복 2·3번(8개 학습)이 300배로 학습됐다. 손실 그림에서 "약 15배" 선이 300배 선과 겹치는 것을 보고 찾았다. 규칙을 고치고 그 8개를 올바른 가중치로 다시 학습했다(00:53~00:57). 이 문서의 숫자는 모두 고친 뒤의 값이다. 잘못된 8개 결과는 `artifacts/risk-loop/resplit-1117/run01/mislabelled_w15/`에 따로 뒀다. 학습과 지표 계산 양쪽에 "실제로 쓴 가중치가 의도한 값인지" 확인을 넣었다.

## 결과

### 1. 정해 둔 레시피 (64차원, 위반 가중치 약 15배, 67 epoch) — 아무것도 고르지 않은 값

| | train (전체 행 재채점) | validation | test |
|---|---|---|---|
| 주 지표 | 1.000 | 0.815 (반복별 1.00 / 0.67 / 0.78) | **0.833** (0.75 / 0.75 / 1.00) |
| 95% 구간 | — | 0.52~1.00 | 0.50~0.91 |
| 넓힌 지표 | 1.000 | 0.522 | 0.722 (구간 0.50~0.89) |
| 같은 도구끼리, 위반 전체 | 0.669 | 0.303 | 0.512 |
| 같은 시기 안, 위반 전체 | 0.716 | 0.570 | 0.636 (10월 0.585, 11월 0.706) |
| 같은 시기 안, 근거가 보인 위반 | 1.000 | 0.746 | 0.738 |
| 오경보 5%에서 잡은 위반 | — | 26개 중 5.7개 | 26개 중 7.3개 (10월 4.0, 11월 3.3) |

학습 데이터에서는 완벽히 가르고(1.000), 학습하지 않은 시나리오에서는 0.8 안팎이다. 근거가 보이지 않은 위반까지 넣으면(같은 도구끼리, 위반 전체) 0.3~0.5로 우연 수준이다. 이 모델은 근거가 보인 위반만 학습했다.

### 2. 미리 정한 규칙으로 고른 모델

규칙: validation의 넓힌 지표가 가장 높은 것. 18개(Argus-V-em 12 + Argus-V-p 6) 가운데 **Argus-V-p P6**(같은 도구 안 학습 + 규제 완화 + 랜덤 포레스트)이 0.800으로 골라졌다.

| Argus-V-p P6 | validation | test |
|---|---|---|
| 주 지표 | 0.667 | **0.708** (구간 0.58~0.85) |
| 넓힌 지표 | 0.800 | 0.667 (구간 0.58~0.88) |
| 같은 도구끼리, 위반 전체 | 0.771 | 0.571 |
| 같은 시기 안, 위반 전체 | 0.564 | 0.604 |
| 오경보 5%에서 잡은 위반 | 26개 중 2개 | 26개 중 4개 |

P6은 train에서 주 지표 1.000이다(학습 데이터를 외우는 설정).

### 3. Argus-V-em: 모델 × 위반 가중치 (67 epoch, test)

test 주 지표:

| 모델 | 약 15배 (지금 방식) | 약 60배 | 300배 |
|---|---|---|---|
| 32차원 | 0.792 | 0.833 | 0.708 |
| 64차원 | **0.833** | 0.917 | 0.542 |
| 128차원 | 0.792 | 0.750 | 0.542 |
| 선형 대조 | 0.792 | 0.625 | 0.500 |

test 넓힌 지표 / 같은 시기 안(위반 전체):

| 모델 | 약 15배 | 약 60배 | 300배 |
|---|---|---|---|
| 32차원 | 0.685 / 0.588 | 0.713 / 0.642 | 0.648 / 0.741 |
| 64차원 | 0.722 / 0.636 | 0.778 / 0.663 | 0.519 / 0.741 |
| 128차원 | 0.750 / 0.696 | 0.694 / 0.686 | 0.583 / 0.774 |
| 선형 대조 | 0.750 / 0.734 | 0.639 / 0.722 | 0.546 / 0.737 |

- 300배는 같은 도구끼리 비교하는 두 지표에서 가장 낮고, "같은 시기 안에서 모든 호출"에서는 가장 높다. 가중치를 키우면 "같은 도구 안에서 위반과 정상을 가르는 것"보다 "위반이 나오는 도구·상황의 호출을 통째로 높게 치는 것" 쪽으로 간다는, 기존 분할에서 본 것과 같은 방향이다.
- 64차원·약 60배의 0.917은 표에서 가장 높은 값이지만 미리 정한 어떤 규칙으로도 골라지지 않는 값이다. 그 설정의 validation 넓힌 지표는 67 epoch에서 0.433으로 가장 낮은 축이고, validation으로 고른 epoch(14)에서는 test 0.625다.
- 임베딩이 없는 선형 대조가 약 15배에서 임베딩 모델과 같은 수준이다(0.792).

### 4. validation으로 고른 epoch에서의 값

모델·가중치마다 validation의 넓힌 지표가 가장 높은 epoch을 골랐을 때의 test 주 지표는 0.50~0.83이다(표 전체는 `tables.md`). 고른 epoch이 12~100으로 제각각이고, validation 값(0.59~0.75)과 test 값 사이에 일정한 관계가 없다.

### 5. Argus-V-p (새 train으로 학습)

| 설정 | train 주 지표 | validation 넓힌 지표 | test 주 지표 | test 넓힌 지표 | test 같은 도구끼리·위반 전체 | test 같은 시기 안 (위반 전체) |
|---|---|---|---|---|---|---|
| P1 최고 모델 그대로 | 0.865 | 0.475 | 0.667 | 0.778 | 0.690 | 0.745 |
| P2 같은 도구 안 학습 | 0.828 | 0.625 | 0.500 | 0.500 | 0.583 | 0.533 |
| P3 규제 완화 | 0.816 | 0.517 | 0.833 | 0.722 | 0.655 | 0.796 |
| P4 같은 도구 안 학습 + 규제 완화 | 1.000 | 0.775 | 0.708 | 0.639 | 0.548 | 0.528 |
| P5 최고 모델 + 랜덤 포레스트 | 0.884 | 0.408 | 0.667 | 0.778 | 0.690 | 0.765 |
| P6 같은 도구 안 학습 + 규제 완화 + 랜덤 포레스트 | 1.000 | 0.800 | 0.708 | 0.667 | 0.571 | 0.604 |

Argus-V-p는 위반 전체를 학습했다. 같은 도구끼리 위반 전체를 재는 값(0.55~0.69)은 Argus-V-em(0.46~0.60)보다 높다.

### 6. test에서 가장 높았던 epoch (참고, 고르는 데 쓰지 않음)

test 값이 가장 높은 epoch을 골라내면 주 지표가 0.65~0.96까지 나온다(64차원·약 15배는 84 epoch에서 0.958). test로 고른 값이라 실제보다 높게 나오는 값이고, 이 문서의 결론에는 쓰지 않았다.

## 읽는 법과 한계

- **말할 수 있는 것**: 새 분할에서, 미리 정해 둔 모델은 학습하지 않은 시나리오의 "근거가 보인 위반"을 같은 도구의 정상 호출과 0.83(test), 0.82(validation)로 갈랐다. 0.90에는 못 미쳤다.
- **말할 수 없는 것**: "0.9에 가깝다"거나 "가중치 60배가 더 좋다". test 위반 4개(24쌍), validation 위반 3개(9쌍)로는 0.1~0.2 차이를 가를 수 없다. 반복(seed)만 바꿔도 test 주 지표가 0.75~1.00으로 움직인다.
- 주 지표는 validation·test 각각 도구 1개, 시나리오 계열 1개에 기댄다. 데이터 전체에 그런 도구가 5개뿐이라 분할을 바꿔도 달라지지 않는다.
- 새 test에는 기존 train에 있던 계열 7개가 들어 있다(`record_independent_review`가 있는 계열 포함). 새 모델의 가중치는 그 데이터를 본 적이 없지만, 모델 구조·근거 표시 규칙·67 epoch이라는 선택은 기존 train의 k-fold 점수를 보며 정한 것이다. 그만큼 test 값은 실제보다 좋게 나왔을 수 있다.
- 새 test를 쓴 것은 이번이 처음이다(`../test-use-log.md`). 이 결과를 보고 설정을 고쳐 같은 test로 다시 재면 그 값은 고른 값이 된다.
- 기존 분할, 기존 모델(Argus-V-p, Argus-V-em, Argus-V-em300)과 그 결과는 그대로다.
