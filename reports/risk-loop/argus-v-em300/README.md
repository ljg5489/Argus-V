# Argus-V-em300 — Argus-V-em을 300 epoch까지 학습

실행 전에 고정함(2026-11-16 19:20 KST). 사용자 지시(2026-11-16):

- "300 epoch까지 학습을 시켜보자. Argus-V-em300이라는 이름으로 기존 Argus-V-em이랑 똑같은데 에폭만 300으로 돌아가게 해."
- "에폭을 돌며 성능지표에 필요한 epoch 정보, 다른 보고에 필요한 학습에 대한 데이터도 저장해."
- "300 epoch까지 돌며 모든 학습이 끝나면 이번에는 정말 TEST 데이터를 가지고 성능평가를 시작해. 이때도 모든 성능평가 데이터를 기록하고."

배경: Argus-V-em(60 epoch)의 epoch 곡선에서, train 분할 안 교차검증 점수(학습에서 뺀 시나리오 묶음, 근거가 보인 위반 기준)가 60 epoch까지 계속 올랐다(0.66 → 0.96). 1 epoch이 가중치를 한 번 고치는 것이라 60 epoch은 학습 초반이다. 더 길게 학습하면 어떻게 되는지 본다.

## 무엇을 학습하나

Argus-V-em round 01과 **epoch 수만 다르다(60 → 300)**. 나머지는 전부 같다.

- 입력: 행동 직전 hidden state에서 만든 `L23:max` + `L16:pre`, 5,760개 값. 도구 이름·step 번호·시나리오 번호는 입력에 없다.
- 구조: 학습 묶음으로 맞춘 robust 스케일링과 자르기 → Linear(5760 → 폭) → LayerNorm → GELU → Dropout 0.15 → Linear(폭 → 1). 폭은 32, 64, 128 세 가지. 대조로 임베딩 없는 선형 모델(Linear(5760 → 1)).
- 정답: 그 호출이 "행동 전에 근거가 보인 위반"이면 1, 정상이면 0(표시 규칙 provisional-1). 근거가 보이지 않은 위반은 학습에서 뺀다.
- 데이터: train 분할만. 정상 호출 9,202개와 근거가 보인 위반 22개 중에서, 칸(도구×출처)마다 정상 호출을 max(30, 위반 수 × 20)개까지 뽑는 규칙 그대로.
- 학습: 전체 행을 한꺼번에 넣는 AdamW(학습률 0.001, weight decay 0.01), 가중 이진 교차 엔트로피(양성 가중치 = 클래스 비율의 제곱근, 상한 20), **300 epoch**. 조기 종료 없음.
- 채점: 시나리오 계열 5묶음 × 나누기 3가지(seed 0·1·2)의 교차검증. sampling·모델 seed는 Argus-V-em과 같다.
- 선택과 저장: 세 폭 중 교차검증 주 지표가 가장 높은 폭을 고르고(Argus-V-em과 같은 규칙), 그 폭을 전체 target 행에 한 번 맞춰 `artifacts/risk-loop/argus-v-em300/argus_v_em300.pt`로 저장한다(seed 910032).
- 점검: 선택된 폭으로 라벨 섞기 5회(Argus-V-em과 같은 seed).

학습 횟수: 묶음 학습 60번(모델 4개 × 15) + 최종 1번 + 라벨 섞기 25번. 노트북 CPU로 약 50분 예상. Argus-V1 루프의 시도 수에는 넣지 않는다.

## 무엇을 기록하나

- epoch마다, 학습 한 번마다: 최적화한 손실, 평가 모드 손실(학습 행·뺀 묶음), 학습 행의 같은 도구 안 AUROC, 기울기 크기, 가중치 크기.
- epoch마다, 나누기마다: 모든 행의 교차검증 점수(나중에 어떤 지표든 다시 계산할 수 있게), 채점 대상별 AUROC(주 지표 / 위반 2개 이상 칸 / 위반 전체), 칸 7개별 AUROC.
- 학습 한 번마다: 행 수, 위반 수, 양성 가중치, 걸린 시간. 실행 전체: 설정, 라이브러리 버전, 시작·종료 시각.
- 최종 모델: 모델 파일, 10 epoch마다의 중간 저장본(60 epoch 포함), epoch마다 모든 행의 점수, 모든 행의 임베딩 벡터.
- 확인: 이 실행의 60 epoch 시점 점수가 저장된 Argus-V-em 점수와 같은지(같아야 "같은 학습을 더 길게 돌린 것"이다).

파일: `results.json`, `epoch_history.json`, `epoch_table.csv`(모델·epoch별 한 줄), `linear_control.json`, `shuffle.json`, 그림은 `figures/`. 큰 배열은 `artifacts/risk-loop/argus-v-em300/`(git 제외).

## 읽는 법과 지킬 것

- 보고하는 점수는 **300 epoch 시점의 값**이다. 곡선에서 가장 높은 epoch의 값을 모델 점수로 쓰지 않는다(참고로만 적는다).
- 여기서 나오는 "검증" 점수는 모두 train 분할 안 교차검증이다. 300이라는 epoch 수는 60 epoch 곡선을 보고 정했으므로 이 점수는 개발용 점수다.
- 학습에는 train 분할만 쓴다. validation·test 행은 학습·선택·설정에 쓰지 않는다.
- 기존 Argus-V-em 파일(모델, 점수, 표)은 바꾸지 않는다.

## 학습이 끝난 뒤: test 평가 (사용자 지시)

학습이 모두 끝나면 저장된 최종 모델을 test 분할로 한 번 채점한다. test를 열기 전에 모델 파일의 SHA-256, 표시 규칙, 라벨 출처, 지표 정의를 `test-eval-prereg.md`에 고정하고, 그 뒤에는 모델을 고치지 않는다. test 결과를 본 뒤에 설정을 바꿔 다시 재면 그것은 더 이상 test 점수가 아니다.
