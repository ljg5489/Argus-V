# Argus-V-emp — Argus-V-em과 Argus-V-p를 섞은 모델 (2026-11-17)

이름은 사용자가 정했다("섞은 모델을 Argus-V-emp로 이름잡고 그것으로 다시 전체 test 진행해봐"). 새로 학습한 것은 없고, 새 분할(`../resplit-1117/`)의 train으로 이미 학습해 둔 모델들의 점수를 섞는다.

## 정의 (test 전체 채점 전에 고정)

- **구성 모델 14종**
  - Argus-V-em 12개 설정: 32차원·64차원·128차원·선형 대조 × 위반 가중치 약 15배·약 60배·300배. 각각 반복 3번, 67 epoch. 점수 36벌.
  - Argus-V-p 2개 설정: P3(규제 완화), P5(최고 모델 + 랜덤 포레스트).
  - 모두 새 분할의 train으로만 학습했다(`../resplit-1117/run01/`).
- **호출 하나의 점수를 내는 법**
  1. 구성 모델마다, 그 모델의 점수를 "validation 호출 가운데 이 모델이 더 낮은 점수를 준 호출의 비율"(0~1)로 바꾼다. 모델마다 점수 단위가 달라서다. 라벨은 쓰지 않는다.
  2. Argus-V-em 36벌의 값을 평균한다.
  3. 그 평균, P3의 값, P5의 값 셋을 같은 비중으로 평균한다. 이것이 Argus-V-emp의 점수(0~1)다.
- 모델은 호출마다 은닉층 값만 본다. 도구 이름과 기록 시기는 입력이 아니다.
- 코드: `experiments/risk_loop/argus_loop/argus_v_emp.py`

## 어떻게 나온 조합인가

2026-11-17에 "AUROC를 높일 방안"을 찾으면서, 저장된 점수만으로 16가지(모델 평균, 모델 섞기, 실행·도구·시기별 점수 보정)를 validation과 test에서 비교했다(`../resplit-1117/run01/auroc_levers.json`). 이 조합이 validation에서 가장 높았다. 그때는 순위를 채점하는 분할 안에서 매겼고, 여기서는 호출 하나만 있어도 점수를 낼 수 있게 validation 호출을 기준으로 고정했다. 두 방식의 값은 사실상 같다(test에서 0.913 대 0.914).

## test 전체 채점 결과

새 분할의 test: 호출 3,220개 = 정상 3,194개 + 위반 26개(근거가 보인 위반 10개). 자세한 표는 `full_test.md`, `classification_test.md`.

| 무엇을 맞히게 했나 | 채점 방법 | Argus-V-em 64차원·약 60배 하나 | **Argus-V-emp** | 95% 구간 |
|---|---|---|---|---|
| 위반 26개 대 정상 3,194개 | 도구·시기 구분 없이 전부 비교 | 0.767 | **0.913** | 0.79~0.96 |
| | 같은 시기의 호출끼리 비교 | 0.663 | **0.822** | 0.64~0.92 |
| | 같은 도구의 호출끼리 비교 (위반 24개) | 0.623 | 0.598 | — |
| 근거가 보인 위반 10개 대 정상 3,194개 | 도구·시기 구분 없이 전부 비교 | 0.838 | **0.962** | 0.90~0.98 |
| | 같은 시기의 호출끼리 비교 | 0.701 | **0.876** | 0.79~0.95 |
| | 같은 도구의 호출끼리 비교 (위반 10개) | 0.774 | 0.776 | — |

validation에서의 Argus-V-emp: 위반 전체 0.837(같은 시기끼리 0.788), 근거가 보인 위반 0.958(0.884).

경보 기준을 정했을 때 잡히는 수:

| 기준 | 위반 26개 중 | 근거가 보인 위반 10개 중 | 정상 3,194개 중 잘못 경보 |
|---|---|---|---|
| validation 정상의 1%가 경보인 문턱 | 2 | 1 | 35 |
| validation 정상의 5%가 경보인 문턱 | 12 | 7 | 145 |
| validation에서 F1이 가장 높은 문턱 | 2 | 1 | 17 |
| (참고) test 정상의 5%가 경보인 문턱 | 13 | 7 | 160 |
| (참고) test 정상의 10%가 경보인 문턱 | 20 | 10 | 320 |

같은 5% 문턱에서 Argus-V-em 64차원·약 60배 하나는 26개 중 9개, 10개 중 4.7개를 잡는다.

근거가 보인 위반 10개는 모두 정상 호출의 91% 이상보다 점수가 높다(가장 낮은 것이 91.8%).

## 읽을 때 알아 둘 것

- **오른 것은 "도구를 가로질러 위험한 호출을 가려내는 능력"이다.** 같은 도구 안에서 위반과 정상을 가르는 값은 그대로다(0.60, 0.78).
- **"전부 비교" 값에는 기록 시기 영향이 섞여 있다.** "10월 기록이면 높게"만 해도 위반 전체 0.750, 근거가 보인 위반 0.861이 나온다. 같은 시기끼리 잰 0.822, 0.876이 그 영향을 뺀 값이다.
- **탐색으로 찾은 조합이다.** 16가지를 비교해 validation에서 가장 좋았던 것이고, 정의를 고정한 것도 test 값을 본 뒤다. 그만큼 실제보다 높게 나왔을 수 있다. 한 번도 쓰지 않은 데이터로 확인한 값이 아니다(봉인 시나리오는 사용자 결정으로 넣지 않았다).
- 근거가 보인 위반 10개는 서로 다른 입력으로 세면 8개다.
- 구성 모델의 epoch에는 둔감하다. 67 대신 1~100 어느 epoch을 써도 근거가 보인 위반의 "전부 비교" 값이 0.95~0.97, 같은 시기끼리 0.81~0.88이다.
- 위반 / 정상 판정기로는 아직 부족하다. 정상의 5%에 경보를 내는 기준에서 경보 157개 중 진짜 위반이 12개(7.6%)다.

## 쓰는 데 필요한 것

지금은 저장된 점수로 평가만 했다. 새 호출에 점수를 내려면 구성 모델이 파일로 있어야 한다. Argus-V-em 구성 모델은 있다(`artifacts/risk-loop/resplit-1117/run01/em/checkpoints/*_e067.pt`). Argus-V-p P3·P5는 점수만 저장했으므로 한 번 다시 맞춰 저장해야 한다(학습이라 사용자 승인 필요).
