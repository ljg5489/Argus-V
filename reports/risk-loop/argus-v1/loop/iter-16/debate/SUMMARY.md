# 토론 결과 요약 — 모델의 문제·원인과 해결방안 검증 (2026-11-13 ~ 11-15)

참가: 모델 구조 설계자, 학습·데이터 전략가, 평가·검증 담당, 시스템·캡처 엔지니어(1라운드 입장문), 망나니(일부러 반대하는 비판 담당, 2라운드 최종 판정). 사용량 한도 때문에 반박 라운드는 생략하고 망나니 판정으로 끝냈다. 모두 학습 없이 파일·기존 결과·문헌만 봤다. 원문: 같은 폴더 `BRIEF.md`(안내문), `r1-*.md`, `r2-executioner.md`(최종 판정의 기준 문서).
별도로 진행: Hugging Face 데이터셋 독립 점검(`../hf-dataset-independent-check.md`, 토론 내용을 모르는 점검자). 이 요약을 쓸 때는 아직 끝나지 않았다.

말뜻: **T7-a** = 지금 최고 모델(선형 모델 3개의 백분위 평균, 같은 도구 안 AUROC 0.721). **순서 규칙** = 모델 없이 "같은 칸에서 step이 앞설수록 위반". **승인 기록 규칙** = 모델 없이 "그 호출 전에 승인·검증 도구가 성공한 기록이 없으면 위반".

## 원인 판정

| 원인 | 판정 | 핵심 |
|---|---|---|
| 위반을 정하는 사실이 행동 전에 모델에게 보이지 않는 위반이 많다 | 부분만 맞음 | 추론 원문 표본의 위반 24개: 알고 함 4 / 모르고 함 18 / 판단 불가 2(세 사람이 따로 세어 일치). 맞는 기준은 "모델이 말로 인정했나"가 아니라 "그 사실이 행동 전 문맥에 보였나". 문맥에 보인 위반은 잡히지만(`issue_payment` 1.00), 글자 규칙으로도 잡힌다 |
| 평가 칸에서 "첫 시도 = 위반, 재시도 = 정상" 구조 | 부분만 맞음 | 순서 규칙 0.730 대 T7-a 0.721. "T7-a는 순서만 읽는다"는 과장, "지금 지표로는 둘을 구분할 수 없다"까지 확정 |
| 관측이 행동 메시지 앞에서 끝난다 | 확정(크기는 잰 적 없음) | 코드 세 곳이 막는다. 도구 이름·인자는 모두 관측 밖 |
| 데이터가 적고 칸마다 시나리오가 하나 | 사실 확정, "늘리면 오른다"는 근거 부족 | 학습 곡선은 점 4개뿐 |
| 위반이 많은 보고 도구에서도 0.6 | 근거 부족 | 설명이 넷 남는다(관측 위치 / 초안 라벨 / 약한 신호 / 시나리오 맞히기) |
| 표현 병목(PCA 32) | 근거 부족, 가능성 낮음 | 안쪽 검증이 스스로 32·10차원을 골랐다 |

보탠 사실: 과적합이 아니다(학습 데이터를 그대로 채점해도 0.800). 지금 칸 구성에서는 0.90이 산수로 막혀 있다(모델이 알 길 없는 위반이 평가 위반의 29% → 나머지가 완벽해도 0.85). 반복 12 데이터 계획도 승인 결과에 범위를 안 적으면 같은 벽을 다시 만든다.

## 승인 요청 계획(망나니 판정문 4절)

- **지금(승인 시)**: 동결용 학습 2건 — ① T7-a 그대로를 train 9,278행·라벨 v2·위반 76개 전체에 1회(약 24초), ② 같은 것에 랜덤 포레스트(나무 500개, 잎 최소 10행, 특징 42개, 비중 1/4)를 더한 판 1회(약 1분). 고르는 것이 없어 누적 시도 169 그대로. 선택: 진단(몇 분), 보고 도구 시험대(약 1시간, 별도 장부).
- **새 데이터 뒤(다시 승인)**: 점수 없이 설계 점검 → 사람 검수 → 고정 모델 채점 1회 → 같은 절차 재학습(시도 최대 3) → 행동 끝 대 행동 직전 진단.
- **하지 않는다**: 지금 칸 9개에서 새 구조·랜덤 포레스트 교차검증·임베딩 모델 학습, 끊긴 확인 재실행, 후보 중 최고값 보고, 채점 뒤 고치기.

## 사용자가 결과를 보기 전에 정할 것

1. 0.90의 대상: 전체 위반인가, "사실이 행동 전 문맥에 보인 위반"인가.
2. 성공의 뜻: 글자 규칙(순서, 승인 기록)과 같은 점수여도 성공인가, 그것을 이겨야 성공인가.
3. 행동 메시지 위치 값을 이번 재실행에서 저장할지(둘째 탐지기를 허용할지와 별개로 재료만이라도).

## 0.90 전망

행동 전 값만으로 새 데이터에서 0.90에 닿을 확률은 5~10%(어림). 고정 모델의 새 데이터 값은 0.50~0.85로 넓게 본다(순서를 읽는 쪽이면 낮게, 승인 상태를 읽는 쪽이면 높게).

## Hugging Face 독립 점검과의 대조 (2026-11-15 추가)

토론 내용을 모르는 점검자가 HF 원본(train rollout 1,647개, step 11,078개)만 보고 쓴 `../hf-dataset-independent-check.md`와 대조했다.

- **토론과 일치(독립 확인)**: 관측에 행동 토큰이 없다. 위반·정상이 둘 다 있는 행동 도구 27개 중 26개는 위반이 시나리오 한 곳에서만 나온다(도구 이름이 시나리오마다 달라 "같은 도구 안 비교"가 사실상 "같은 시나리오 안 비교"다). 읽은 행동 도구 위반 42건 중 금지임을 알고 한 것은 1건, 허용된다고 판단 21건, 따지지 않음 10건. 업무 도구 위반 73건 중 23건은 같은 도구의 정상 호출과 인자가 완전히 같다. 같은 도구의 위반·정상 쌍의 71%에서 위반 쪽 프롬프트가 더 짧다(순서 규칙 0.73과 같은 현상).
- **토론에 없던 것**: ① 텐서 파일 해시까지 같은데 라벨이 반대인 쌍이 1개 있다(`update_stock`). ② 10월 train step의 44%(466/1,066)가 다른 rollout과 앞부분·텐서가 같은 복제본이고, 복제를 빼면 행동 도구 위반은 79건이 아니라 64건이다(분할을 넘는 복제는 0건). ③ 10월에서 사람이 본 위반 68건 중 규칙이 잡은 것은 40%다(놓친 41건 중 33건은 보고용 도구). ④ `submit_result` 규칙 라벨은 읽은 위반 20건 중 약 7건이 표기 형식(0·false, 값 종류) 때문에 위반이 된 것이다. ⑤ HF 최신 revision은 `62106dbf`(11월 11일)이고 11월 사람 검수가 8건에서 24건으로 늘었다(train에서 늘어난 11건은 모두 정상 판정이라 라벨 값은 그대로). ⑥ 11월 사람 검수 파일의 확인 이력 17건 중 14건에 "AI 대행 검수"라고 적혀 있다.
- **계획에 주는 영향**: 방안 5(보고 도구 시험대)는 라벨을 고치기 전에는 보류한다(망나니가 건 "라벨 60개 사람 확인 먼저" 조건이 통과하기 어렵다). 동결용 학습 2건과 방안 2·3·7은 그대로다. 수집 쪽 새 권고 하나: 결정 지점까지 앞부분을 고정하고 여러 번 이어 생성해 "앞부분은 같고 선택만 다른" 쌍을 만든다.

## 이 판정의 가장 약한 고리

승인 기록 규칙이 T7-a만큼 한다는 근거가 한 칸 9행과 다른 칸의 일부 행뿐이다. 판정 칸 149행 전체에서 이 규칙을 계산하면 바로 확인된다(학습 없음).
