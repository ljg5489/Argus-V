읽기만 했다(코드, 인계서, 실행 기록, train rollout 기록 4개의 토큰 위치 숫자). 학습·실행·재현 시험은 하지 않았다. 웹 검색 9건.

## 1. 원인 검토

- **원인 3은 맞다. 코드가 세 겹으로 막는다.** ① `argus_hook/scenario_rollout.py` 434–447행: 관측 지점은 프롬프트 끝, 추론 N토큰마다, 추론 끝, 행동 메시지 바로 앞뿐이고, 445–446행은 그 뒤 지점이 있으면 오류를 낸다. ② 797행: 다시 계산할 때 넣는 입력이 `all_ids[:action_start]`라서 행동 토큰은 계산에 들어가지도 않는다. ③ `src/argus_v/activations/alignment.py` 60–61행: "행동 전" 캡처의 입력이 행동 시작을 넘으면 오류. 행동 메시지는 표본(step 34개)에서 평균 47토큰(21~213)이고, 도구 이름과 인자는 모두 그 안에 있다.
- 다만 원인 3이 **점수를 얼마나 깎는지는 모른다**(인자가 추론에 미리 적히는 경우가 많다). 행동 위치 값을 저장해야만 잴 수 있다.
- **빠진 점**: 행동은 관측 뒤에 무작위로 뽑힌다(temperature 1.0, 1097–1098행). 같은 "행동 전" 상태에서 위반 인자와 정상 인자가 둘 다 나올 수 있다면 행동 전 입력의 상한은 1보다 낮다(크기는 확인 못 함).
- **원인 5는 해석을 고친다.** 보고 위반은 보고 "내용"이 틀린 것이고, 그 내용은 관측 지점 뒤에 쓰인다. 0.59~0.63은 "데이터가 많아도 안 된다"가 아니라 원인 3의 다른 예일 수 있다.
- 원인 1·2·4는 동의, 6은 미확인 그대로.

**방안 2 — 채택(조건부). 재실행 전에 정해야 한다**(올린 뒤 같은 단위에 파일을 덧붙이는 길은 확인 못 함).

- 바꿀 것: `scenario_rollout.py` 798행 뒤에 두 번째 캡처 호출과 행동 구간 지점 함수를 넣는다(입력은 토큰 전체, 폴더는 `capture_action/`로 분리, 명령 인자는 기본 꺼짐; 약 50줄과 시험). 기존 관측 정의와 "행동 토큰이 포함되면 오류" 검사(445–446행)는 그대로 둔다. 새 캡처는 계약에 이미 있는 "실행 전(pre_execution)" 단계를 쓴다(`alignment.py` 62–64행). 추출·저장·업로드 코드는 그대로다(폴더 안 npz를 모두 올림, `scripts/upload_raw_data_to_hf.py` 234–258행). 특징 생성은 `capture/features.npz`만 읽어서(`build_features.py` 85행) 주 탐지기에 섞이지 않고, 모르는 관측 종류는 191–192행이 오류로 막는다. 실행 전 탐지기용 캐시는 별도 폴더로 새로 만든다.
- 호환·시간: 계산을 한 번 더 하는 방식이라 기존 `capture/`는 지금과 똑같다. rollout 시간은 +5~25% 추정(확인 못 함, 4090에서 2~3개로 먼저 잰다). 이어 돌리기는 이 설정을 보지 않으므로 빈 출력 폴더에서 시작한다(1062–1076행).
- 저장량(지점 하나 = 24층 × 2880 × float32 = 0.28MB, 압축 전):

| 추가로 저장 | step당 | 지금 계획(8토큰 격자 7.0MB) 대비 | step 1,000개당 |
|---|---|---|---|
| 마지막 내용 토큰 1개 | +0.28MB | +4% | +0.28GB |
| + 끝 표시 토큰(**권고, 2개**) | +0.55MB | +8% | +0.55GB |
| + 인자 구간 8토큰마다(최대 8개, 표본 평균 약 4개) | +1.6MB | +23% | +1.6GB |
| 행동 메시지의 모든 토큰(평균 47개) | +13MB | +185% | +13GB |

- 가장 싼 위치는 **마지막 내용 토큰**(끝 표시 `<|call|>` 바로 앞)이다. 호출 전체를 읽은 상태이고, 실제 생성 중에는 이미 계산돼 있어 추가 계산이 0이며, 문헌도 이 위치를 쓴다(Yeats 2026). "도구 이름 직후"는 호출 형식이 두 가지(머리말에 이름 / 본문 JSON에 이름)라 위치가 흔들려 권하지 않는다.
- 옛 데이터: 10월·11월에는 이 값이 없다. 실행 전 탐지기는 새 데이터 안에서만 학습·평가하고, 지금 평가 칸 9개와는 직접 비교 못 한다. 필요하면 저장된 토큰 ID(`agent-generation.json`)로 4090에서 계산만 다시 돌려 채울 수 있다(옛 행동 약 2만 개, 2지점 약 11GB; GPU 시간은 확인 못 함).
- 실시간 차단: 하네스(에이전트 실행 틀)는 이미 "행동 해석 → 캡처 → 실행" 순서다(790–819행). 쉬운 길은 지금처럼 다시 계산하는 것(행동마다 계산 1회만큼 지연). 빠른 길은 생성 중에 중간값을 읽는 것(추가 계산 0, Shu 2026)인데, 생성 중 값과 다시 계산한 값이 같은지 검사한 적이 아직 없다.
- 조건: 주 탐지기 입력 규칙은 그대로 둔다. 실행 전 탐지기는 "행동 글자만 보는" 기준선과 쌍둥이 조건에서 비교한다(행동 토큰을 보면 인자 문자열 암기가 지름길이 된다).

**방안 8 — 조건부 채택. 커밋과 실행기 수정은 지금, 재실행은 따로 판단한다.**

- 0.06초 "완료"의 유력한 원인: 출력 파일을 열지 못하면 cmd는 명령을 실행하지 않고 오류 코드도 바꾸지 않는다(알려진 동작, 출처 6). `run_s1.cmd` 39–46행은 남아 있던 0을 보고 완료 표시를 쓴다. 근거: 0.06초는 파이썬 시작보다 짧다(기록만 하고 끝난 단계도 11~17초). `stage_confirm.out`은 03:13:25 뒤로 한 줄도 늘지 않았다. 건너뛴 두 단계는 0.03초 전에 끝난 단계와 **같은** 출력 파일을 썼고, 다른 파일을 쓰는 다음 단계는 정상 실행됐다. 파일을 잡고 있던 쪽(방금 끝난 프로세스의 자식 작업자, 백신, 로그를 보던 프로그램)은 확인 못 함.
- 재발 방지: ① 완료 표시는 결과 파일(`<구조>/<단계>.json`)이 이번 실행에서 새로 생겼을 때만 쓴다. ② 명령 뒤에 `|| set RC=!errorlevel!`를 붙인다(이렇게 쓸 때만 출력 파일 열기 실패가 오류 코드 1로 잡힌다). ③ 출력 파일을 단계·구조·시각별로 나눈다. ④ `run_rf.cmd` 26·32행의 `if errorlevel 1`은 음수 코드(이미 한 번 난 -1073741819)를 성공으로 본다 → `if not "%errorlevel%"=="0"`. 22행 `timeout`은 콘솔 없이 띄우면 바로 끝나 헛돌 수 있고, 상대 실행기가 표시 없이 죽으면 영원히 기다린다 → 대기 상한.
- 이 노트북 조건(RAM 15.5GB, 지금 여유 2.6GB): 단독 실행, 시작 여유 3GB 이상, 작업자 2개 × 스레드 2개 이하(지난 기록: 여유 0.5~2.5GB, 메모리 접근 위반 1회), 절전 끄기(11일 04:44~13:54 공백). `run_rf.cmd`는 띄우지 않는다: `ALL_DONE`이 생기면 승인 없이 랜덤 포레스트 학습을 시작한다(지금 대기 프로세스 없음, 확인함).
- 남은 양: 확인 2개(각 적합 약 350회, 앞 구조들은 7~95분) + 재선택 남은 5/125 작업(약 30분) + 보고 = 2~4시간 추정.
- 반대 의견: 두 구조는 정직한 교차검증 값이 0.553·0.480으로 T7-a보다 낮아, 재실행은 어떤 결정도 바꾸지 않는다. "실행 안 함"을 사전 등록에서 벗어난 점으로 적고 닫는 선택지도 함께 낸다. 커밋은 재실행과 묶지 말고 먼저 한다(추적 안 된 코드·보고서가 이 노트북에만 있다).

## 3. 0.90에 대한 판단

- "행동 전 값만"으로 판정 지표 0.90은 새 데이터가 와도 **가능성이 낮다.** 시나리오를 학습에 보여 준 낙관 조건에서도 고정 설정은 0.62~0.81이었다. 문헌에서도 오류 신호는 답·호출 토큰 위치에 몰리고(Orgad 2024, Yeats 2026), 탐침은 처음 보는 분포로 잘 옮겨지지 않는다(Kramár 2026).
- 기대(추정): 새 데이터에서 동결 T7-a 0.60~0.75(step 순서만으로 0.73이 나오던 신호가 사라질 수 있다). "알고 한 위반만" 0.70~0.85(결정은 행동 전에 읽힌다는 문헌은 0.89~0.96이지만 같은 분포 안, Sun 2026). 행동 위치를 쓰는 실행 전 탐지기 0.75~0.88(Yeats 2026은 대부분 0.80 이상이지만 같은 벤치마크 안).
- 사용자가 정할 것: ① 0.90을 "알고 한 위반"에 둘지 전체에 둘지. ② 행동 토큰까지 보는 "실행 전 탐지"를 별도 목표로 인정할지(재료 저장은 지금 승인 권고). ③ 동결 모델 1회 확인이 미달이면 어디서 멈출지.

## 4. 승인받을 다음 학습 계획 (한 가지)

지금 최고 모델 T7-a를 그대로(층 23 관측 지점별 최댓값 + 층 16 행동 직전 값 → 척도 맞춤·±3 자르기 → PCA 32/10 → 선형 모델 3개의 백분위 평균, 구조·조정값 탐색 없음) 지금 train 전체(10월·11월, 위반 76개)로 **최종 적합 1회** 해서 파일 해시를 고정한다(CPU 수 분 추정). 새 rollout이 올라오고 판정 칸 도구 행의 사람 검수가 끝난 뒤, 새 데이터에서 **1회 채점**한다(추가 학습 없음, 보조 지표와 step 순서 기준선을 같은 표에). 시도 수 1(랜덤 포레스트를 넣은 판도 함께 동결하면 2). 함께 승인받을 것: 재실행 명령에 행동 위치 저장(2지점, +8%)을 켠다. 실행 전 탐지기 학습은 입력 규칙 변경을 승인받은 뒤 별도 계획으로 낸다.
