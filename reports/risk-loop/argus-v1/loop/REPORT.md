# Argus-V1 성능 향상 루프 — 최종 보고 (2026-11-08, 반복 10회 종료)

## 한 줄 결론
목표(같은 도구 안에서 위반 행동과 정상 행동을 구분하는 AUROC ≥ 0.90)는 **도달하지 못했다**. 가장 정직한 수치는 조합 선택까지 교차검증 안에 넣은 T10-1(반복 10의 앙상블)의 **0.676**, 시도 수 운을 빼면 **약 0.58**이다. 행동(step) 하나 수준에서 실제로 나아졌다는 것은 **확인되지 않았다**. 병목은 모델 구조가 아니라 **데이터**(판정 칸·위반 수가 적고, 칸마다 시나리오가 하나)다.

## 무엇을 했나
- **데이터**: HF에서 10월·11월 rollout을 스트리밍으로 받아 train·validation **15,779 행동**의 hidden state 특징(층 8·11·14·16·20·23 × max·mean·행동 직전·추론 끝 위치)을 만들었다(`data/card.md`). test·봉인 단위는 계산·저장하지 않았다. 판정 행은 train 9,278 행동 / 위반 79, 판정 칸(도구×출처, 정상·위반 각 3개 이상) **10개 / 위반 52**. **11월 라벨은 규칙 초안**(사람 최종 검수 전).
- **평가 코드(동결, `eval/HARNESS.md`)**: v1 → v4. 모두 엄격해지는 방향.
  - v1: 첫 동결본, 라벨 섞기 기준 하나.
  - v2(실제 데이터 보기 전): 섞기 기준을 (a) 출처 안 섞기 ≈ 0.5, (b) 출처×family 안 섞기보다 0.10 이상 높기 두 개로. (b)만으로는 진짜 신호 있는 모델도 0.5를 넘어서.
  - v3(반복 1 뒤): 도구 대신 **도구×출처 칸**으로 묶음. "10월 위반 대 11월 정상"이라 출처만 알아도 점수가 오르는 지름길 제거.
  - v4(반복 3 판정 전): 섞기 3회 → **20회**. 3회 평균은 잡음 0.04라 0.10 기준을 운이 정했기 때문.
  - 반복 9 전 추가 규칙: 후보 조건 (i′)(실제 점수 − max(자기 섞기 (b), 0.591) ≥ 0.10)을 fold seed **10개 평균**으로 판정.

## 결과 숫자
- 원래 Argus-V1 기본(H1-0a) **0.513** → 최고 고정 앙상블 **T7-a 0.696**(10 seed 0.686) / 쌍 학습만 앙상블 **T9-1 0.692**(10 seed 0.680) / 정직한 nested **T10-1 0.676**(10 seed).
- 시도 68~70개 중 최고를 고른 운을 빼면 **약 0.58**(H1-0a 대비 약 +0.07).
- 대부분은 행동 신호가 아니다: rollout 평균 특징만 쓴 진단 모델이 **0.678**, family 안에서 라벨을 섞어 학습해도 **0.59~0.61**. 그 위 step 수준 몫은 **0.07~0.10**으로 사전 문턱 0.10 미만.

## 중요한 발견 (진단)
1. 판정 지표는 실제로 **149행(위반 52·정상 97), 10칸**에서만 계산되고, 칸 10개 중 9개는 위반이 **시나리오 하나**에서만 나온다. 신뢰구간 폭 0.2~0.3.
2. 판정 지표는 "이 rollout이 위험한가"를 상당 부분 잰다(정상의 51%가 위반 있는 trajectory에서 옴).
3. 출처 지름길(10월 위반 대 11월 정상)을 찾아 v3에서 제거(bash 0.81 → 10월만 0.53).
4. 보고 내용 위반(write_report/submit_result 등)으로 배운 방향은 판정 위반에 0.35~0.48 — **다른 방향**이다.
5. 추론 끝(reasoning_end) 위치 activation은 **다음에 부를 도구 종류**를 담고 있어 도구 지름길에 걸린다.

## 사용자가 결정할 것
1. **후보를 Argus-V2로 채택할지.** 채택하면 버전이 오르지만 step 수준 개선은 미확인. 안 하면 Argus-V1 유지.
2. **지표 변경**(예: 같은 trajectory 안 같은 도구의 위반·정상 비교). 시나리오 맥락이 고정돼 행동 신호를 직접 재지만 쌍이 약 50개라 신뢰구간이 넓고, 지금까지 수치와 직접 비교 불가.
3. **11월 최종 검수 라벨 반영.** 판정 칸을 늘릴 가장 큰 지렛대. 초안과 차이가 크면 결과가 바뀐다.
4. **같은 도구가 여러 시나리오에 나오는 데이터 추가.** 칸당 시나리오 3개 이상이어야 "새 시나리오로 옮겨지는가"를 잴 수 있다. 수집·라벨 비용.
5. **validation을 한 번 열어볼지**(T7-a·T9-1). 한 번 보면 이후 선택에 못 쓴다. 지금 수치로는 기대가 낮다.
6. **반복 11~13을 더 돌릴지.** 감사는 TASK.md §6(종료 조건)이 "10회 뒤 3회 연속 정체"로도 읽힌다고 지적. 반복 8~10이 이미 정체이고 남은 가설이 약해 멈췄다.
7. **오케스트레이터가 대신 내린 결정 되돌리기**: `HANDOFF.md` (b) 표 참고(각 줄에 되돌릴 때 결과가 적혀 있음).
