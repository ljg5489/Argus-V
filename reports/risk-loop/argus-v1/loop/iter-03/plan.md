## fold 안전 설계 (H3-1·H3-2 공통)

평가 코드는 headline 행만 보고 fold를 만들고, `fit_predict(pos_train, y_train, pos_test)`에 headline 행 위치만 넘긴다(안쪽 nested fold에서도 같은 위치 번호). 그래서 확장 행은 `fit_predict` 안에서 더한다.

1. headline 행 + 보고 행을 합친 전체 학습 후보에서 (family, trajectory, unit) 연결 성분을 평가 코드 `group_components`로 계산한다.
2. 한 번의 `fit_predict` 호출에서 보고 행은 **그 성분이 `pos_train`에 있고 `pos_test`에는 없을 때만** 더한다. 바깥 fold의 평가 행은 안쪽 호출의 `pos_train`·`pos_test` 어디에도 없으므로, 바깥 평가 family의 보고 행은 안쪽 격자 선택에도 들어가지 않는다.
3. 매 호출에서 "더한 보고 행의 family ∩ `pos_test`의 family = 없음"을 확인하고, 어기면 오류로 멈춘다.
4. 보고 행 라벨은 실제 라벨이다. 평가 코드의 섞기 시험은 headline 학습 라벨만 섞으므로 보고 행 라벨은 그대로 남는다(아래 섞기 두 가지 참고).

## 섞기 시험 두 가지 (사전 등록)

- **평가 코드 그대로**(`evaluate(n_shuffle=10)`): headline 라벨만 섞고 보고 행 라벨은 진짜. 보고 행에서 배운 진짜 신호가 섞기 값에도 남는다.
- **전체 섞기**(`shuffle_test`를 직접 호출, n=10, (a) 출처 안 / (b) 출처×family 안): 보고 행 라벨도 같은 칸 규칙으로 섞는다(난수는 `pos_train`·섞인 `y_train`의 hash에서 만들어 반복마다 다름). "family 정보만으로 얻는 점수"의 올바른 영가설이다.
- **후보 조건의 섞기 (b) 값은 둘 중 큰 값**을 쓴다(보수적).

## 가설과 시도 (새 시도 ≤ 12개, 계획 10개 + 여유 2개)

기본 표현은 층 23 max, 기본 모델은 반복 2 최고 H2-1c(정상 가중치 상향 LogReg, 학습 가중치 출처×클래스). 확장 행 가중치 w = 0이면 H2-1c와 점수가 똑같음을 단위 시험으로 확인한다(새 시도 아님).

가중치 정의: headline 학습 행은 H2-1c와 같다(총합 = headline 학습 행 수). 보고 행은 (출처 × 클래스) 칸마다 같은 총합이 되게 나누고, 보고 행 전체 총합을 w × (headline 학습 행 수)로 둔다.

### H3-1 학습 데이터 확장 (A단계, 5개)

- **H3-1a**: 보고 행(정상+위반) w = 1
- **H3-1b**: 보고 행(정상+위반) w = 0.3
- **H3-1c**: 보고 위반 행만 w = 0.3 (보고 위반 총합 = 0.3 × headline 위반 총합 수준)
- **H3-1d**: 보고 행 w = 1을 반복 1 모델(`pca_logreg` 방식, 정상 가중치 상향 없음)에 붙임 — 확장 효과가 H2-1c에만 묶인 것인지 확인
- **H3-1e**: 보고 행 w = 1, 보고 행 가중치를 (family × 클래스) 칸마다 같게(F06 한 family가 11월 보고 위반 359개 중 107개라서, 한 시나리오 방향만 배우지 않게)

### H3-2 다중 과제 (B단계, 2개)

- PCA는 공유(headline + 보고 학습 행). 선형 점수 = 공유 w0 + 과제별 w_task(행동/보고). 특징을 [E, 행동이면 E, 보고면 E]로 늘려 L2 LogReg 하나로 학습(과제 표시는 학습 행에서만, 점수 시점에는 과제를 묻지 않고 항상 아래 고정식 사용). 가중치는 A단계 최고 확장 설정(없으면 H3-1a).
- **H3-2a**: 점수 = E·(w0 + w_action)
- **H3-2b**: 점수 = E·w0 (공유 방향만)

### H3-3 이전 step 맥락 (C단계, 3개)

- 같은 trajectory에서 step_index가 바로 앞인 행(전체 학습 후보 행: headline + 보고 행 중)의 같은 층 특징. 이전 step이 없으면 자기 자신 값(변화 0). 이후 step은 쓰지 않는다. 도구 이름·라벨은 쓰지 않는다.
- **H3-3a**: [x_t, x_prev] 연결(블록별 표준화, 같은 비중) + A∪B 최고 설정
- **H3-3b**: x_t − x_prev + A∪B 최고 설정
- **H3-3c**: [x_t, x_prev] 연결 + H2-1c(확장 없음) — A∪B 최고가 이미 H2-1c 같은 확장 없음이면 대신 여유로 둔다

### 여유 2개

- 분명한 다음 단계가 보이면 쓰고 이유를 cv_report에 적는다. 누적 시도 45 + 최대 12 = 57.

## 선택 규칙 (사전 등록)

1. 순위: nested CV **seed 평균 v3 같은 도구 안 AUROC**가 높은 순. 0.005 이내면 단순한 쪽(확장 없음 < 확장 < 다중 과제 < 이전 step) 먼저.
2. 상위 3개는 `evaluate.evaluate(n_shuffle=10)` 전체 + 전체 섞기 n=10 (a)(b). 재계산은 새 시도로 세지 않는다.
3. **후보 인정 조건**(모두 만족): (i) 같은 도구 안 − max(섞기 (b) 두 가지 평균) ≥ 0.10, (ii) 같은 도구 안 − 길이+step 기준선(같은 fold, 반복 2 값 0.522) ≥ 0.05. 아니면 "후보 없음".
4. 누적 시도 > 30 → 감시 규칙 R1: 이전 최고(H2-1c 0.645)보다 0.12 이상, seed 3개·두 출처 모두 같은 방향일 때만 "실제 개선"으로 적는다(R2 운 보정도 적는다). 판정은 평가 에이전트.
