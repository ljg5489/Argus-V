지시: 사용자가 2026-11-11에 "2번 방식"(T7-a 앙상블에 랜덤 포레스트를 4번째 구성원으로 추가)을 직접 지시했다.
데이터: 반복 14와 같다. train split, 판정 행동 9,278개, **학습 위반 76 / 평가 위반 48**(평가는 도구×출처 칸 9개). 라벨 v2, 평가 코드 evaluate.py v4(sha `a7c36eaf…df0130d`, 바꾸지 않음).
용어: **T7-a** = 지금까지 가장 좋은 모델. 선형(로지스틱) 모델 3개의 점수를 각각 "학습 행 점수 중 몇 % 위치인가"(백분위)로 바꿔 똑같이 평균한 것. fold seed 0–2 값 0.714. **랜덤 포레스트(RF)** = 결정 나무 여러 개의 평균. 선형 모델이 못 잡는 특징 사이의 조합(비선형 관계)을 잡을 수 있다.

## 1. 왜 하는가
- T7-a의 세 구성원은 모두 선형이다. 같은 도구 안에서 위반과 정상을 가르는 경계가 직선이 아니면 셋 다 놓친다.
- 반복 14에서 "도구를 넘는 정보를 버리는" 방향(같은 도구 안 학습)은 T7-a를 0.714 → 0.60–0.66으로 낮췄다. 그래서 이번에는 **T7-a는 그대로 두고**, 같은 입력 위에 비선형 구성원 하나를 더해 본다.
- RF는 특징 크기·단조 변환에 영향을 받지 않고, 작은 데이터에서도 조정값이 적어 과적합 위험이 비교적 작다.

## 2. 방법

### 2.1 입력 (T7-a와 같은 fold 안 표현)
- T7-a가 이미 쓰는 fold 안 robust 표현(`iter07_models.RobustStore`: 학습 행으로 중앙값·IQR 척도 → ±3 자르기 → 학습 행으로 PCA)을 그대로 쓴다.
- RF 입력 = **층 23 최댓값 PCA 앞 32차원 + 층 16 행동 직전 PCA 앞 10차원 = 42개 특징**. 구성원 ①②(층 23 최댓값 32)와 ③(층 16 행동 직전 10)의 입력을 이어 붙인 것이다.
- 척도·PCA는 그 적합의 학습 행으로만 맞춘다(바깥 평가 때는 바깥 학습 fold, 안쪽 조정값 선택 때는 안쪽 학습 행만).

### 2.2 랜덤 포레스트
- `sklearn.ensemble.RandomForestClassifier(n_estimators=500, max_features="sqrt", bootstrap=True, random_state=0, n_jobs=2)`, sklearn 1.8.0.
- **min_samples_leaf ∈ {5, 10, 20}** (잎 하나에 들어가야 하는 최소 행 수; 클수록 덜 과적합). 반복 14와 같은 안쪽 family CV-4(evaluate.nested_cv, inner_splits 4)가 **시도마다** 고른다(R1·R2는 4개 평균 점수의 안쪽 같은 도구 안 AUROC로 고른다). 조정값 선택은 시도 수에 넣지 않는다.
- 예측 때는 나무 점수를 고정된 순서로 더한다(`n_jobs=1`로 바꿔 예측) → 같은 입력이면 비트 단위로 같은 점수(시험으로 확인).

### 2.3 점수 → 백분위 (학습 행 기준표) — **학습 행의 in-sample 점수로 정함**
- RF 점수 = 나무 500개의 P(위반) 평균(`predict_proba[:, 1]`). 다른 구성원과 똑같이 `iter06_models.train_percentile`로 **그 적합의 학습 행 점수 중 위치(중간 순위 백분위)**로 바꾼다.
- 기준표는 **학습 행의 in-sample 점수**(학습한 RF로 학습 행 자신을 채점한 값)다. 반복 6·12·14의 T7-a와 똑같은 관례다.
- 우려: RF는 학습 행에 과적합해서 in-sample 점수가 0/1 쪽으로 몰릴 수 있고, 그러면 기준표가 찌그러져(평가 행 여러 개가 같은 백분위로 묶여) 순위 정보가 사라질 수 있다. 대안은 out-of-bag 점수(각 학습 행을 그 행을 안 본 나무들로만 채점한 값)로 기준표를 만드는 것이다.
- **결정 근거(합성 데이터, 실제 데이터 보기 전)**: 실제 크기(학습 7,422행 × 42특징, 학습 위반 59개, 평가 1,856행 중 위반 17개, min_samples_leaf 5, 가중치 있음)의 합성 데이터에서:

  | 기준표 | 평가 정상 행 평균 백분위(이상적 0.5) | 서로 다른 백분위 수 / 서로 다른 원점수 수 | 백분위의 AUROC (원점수 AUROC 0.796) |
  |---|---|---|---|
  | in-sample (채택) | 0.568 | 1,325 / 1,666 | **0.797** (원점수와 같음) |
  | out-of-bag | 0.513 | 692 / 1,666 | 0.792 (조금 잃음) |

  in-sample 기준표는 찌그러지지 않았다(학습 위반의 in-sample 점수 중앙값은 0.65로 높지만, 학습 행의 99%인 정상 행의 점수는 평가 행과 비슷하게 퍼져 있다). out-of-bag 쪽은 행마다 약 180개 나무 평균이라 값이 성글어 **동점이 더 많고** 순위 정보를 더 잃었다. out-of-bag의 장점(정상 평가 행이 0.5 근처에 놓임)은 작았다(0.568 vs 0.513). → **in-sample을 쓴다.** out-of-bag 코드는 이 비교용으로만 남기고 실행에서는 쓰지 않는다.
- 실제 데이터에서는 적합마다 "평가 행의 서로 다른 백분위 수 / 서로 다른 원점수 수"를 기록해 보고한다(찌그러짐 감시). **이 값으로 기준표를 바꾸지 않는다**(결과를 본 뒤 바꾸면 갈림길이 하나 더 생김).

### 2.4 학습 행 가중치 — **T7-a 구성원 ①과 같은 가중치를 sample_weight로**
- 구성원 ①(점별 로지스틱, 기존 이름 H2-1c)의 가중치를 그대로 쓴다: 출처×클래스 균형 가중치(`models.sample_weights(..., "source_class")`) → 위반과 정상이 둘 다 있는 학습 칸의 정상 행을 정상 전체 가중치의 절반까지 올림(`models.informative_group_weights`). 칸 = 도구×출처, 학습 행에서만 읽는다.
- **`class_weight`는 쓰지 않는다(None).** 지시 초안의 `class_weight="balanced_subsample"`을 같이 켜면, sklearn은 그 가중치를 sample_weight에 **곱한다**(sklearn 1.8 `_forest.py`에서 확인). 출처×클래스 가중치가 이미 위반과 정상의 총 가중치를 맞추므로, 둘 다 켜면 위반 가중치가 한 번 더 약 60배 커진다(클래스 균형 두 번). 그래서 "구성원 ①의 가중치"를 택하고 `class_weight`는 끈다. (가중치를 못 쓰는 경우의 대안이던 "단순 balanced_subsample"은 쓰지 않는다.)
- bootstrap 표본은 균일하게 뽑히고(가중치는 뽑힌 횟수에 곱해짐), min_samples_leaf는 가중치가 아니라 행 수로 센다.

### 2.5 세 시도
| 시도 | 내용 | 역할 |
|---|---|---|
| **R0** | RF 하나만(백분위 점수 그대로) | 비교용. RF가 혼자서 얼마나 되는지 |
| **R1** | T7-a 세 구성원 + RF = **4개 구성원 백분위의 똑같은 평균(각 1/4)** | **주 시도** |
| **R2** | R1과 같되, RF를 **칸별 중심화한 특징**으로 학습 | 반복 14 W1의 RF판 |

- R1 점수 = ¾ × (T7-a 세 구성원 백분위 평균) + ¼ × RF 백분위 = 네 백분위의 단순 평균. T7-a 부분은 `within_tool.T7aW`(방법 없음)를 그대로 부른다. RF 비중을 0으로 두면 T7-a와 비트 단위로 같다(시험).
- R2의 칸별 중심화: 학습 fold 안에서 42개 특징 각각에서 **각 칸(도구×출처)의 학습 행 평균을 뺀 값**으로 RF를 학습한다. 점수를 매길 때와 백분위 기준표(학습 행 점수)를 만들 때는 **중심화하지 않은 원래 특징**을 넣는다(점수 때는 도구 이름을 쓸 수 없으므로). RF는 비선형이라 반복 14의 선형 경우처럼 "칸 상수가 정확히 빠진다"는 성질이 **없다 — 근사다.** 칸 평균은 그 적합의 학습 행으로만 계산하고(안쪽 선택 때는 안쪽 학습 행만), 실제로 쓰인 행 목록을 적합마다 검사한다(`within_tool.center_audit`).
- RF를 학습할 수 없는 경우(학습 행에 한 클래스만 있음)는 iter06처럼 모든 점수 0 → 백분위 0.5.

## 4. 평가 (반복 14의 T7-a 기반과 같은 절차)
- 평가 코드 evaluate.py v4(sha `a7c36eaf…df0130d`), 같은 도구 안 AUROC(도구×출처 칸 9개, 평가 위반 48 / 학습 위반 76).
- 바깥: family StratifiedGroupKFold-5(evaluate.make_folds), **fold seed 0·1·2**. min_samples_leaf는 바깥 학습 fold 안의 family CV-4가 고른다. **nested 값이 공식 숫자**이고, CI는 evaluate.metrics의 family 부트스트랩(2,000회, seed 0).
- **T7-a 대비 이득**: 같은 실행에서 T7-a(방법 없음, fold seed 0–2)를 다시 계산하고(예상 ≈ 0.714; 반복 14 OOF와의 최대 차이도 보고), 같은 family 재표본에서 두 모델의 seed 평균 같은 도구 안 AUROC 차이(`within_tool.paired_gain`, 2,000회, seed 0). 참고용으로 R1−R0, R2−R1, R2−R0도 같은 방식으로 보고한다.
- **행동 직전만 쓰는 대조군**(시도마다, 같은 격자·같은 안쪽 CV-4): 반복 14처럼 모든 구성원의 표현을 행동 직전 위치로 바꾼다 — T7-a 구성원은 층 23 행동 직전 ×2, 층 16 행동 직전(`within_tool.T7A_PRE_REPS`), RF 입력은 층 23 행동 직전 32 + 층 16 행동 직전 10.
- **라벨 섞기** (a) 출처 안, (b) 출처×family 안, 각 20회, fold seed 0, 그 시도의 nested에서 가장 많이 고른 min_samples_leaf 고정(evaluate.shuffle_test, perm_seed 0). R1·R2의 섞기에서는 T7-a 구성원도 섞인 라벨로 다시 학습된다.
- **운 보정**: 값 − 0.05·E[정규분포 N개 최댓값], N = 172(보수 174도 같이).
- **K1**(관측 지점 전체/풀링이 행동 직전만보다 나은가): 본 시도 − 자기 행동 직전 대조군의 짝 부트스트랩 이득, CI 하한 ≤ 0이면 실패.
- **K3**(점수가 단순히 "관측 지점이 많은 행"을 높게 주는가): 칸마다 점수와 관측 지점 수(32토큰 격자, 관측 캐시 `n_obs32`)의 Spearman |ρ|, 위반 수 가중 평균, seed 평균(사이클 1 코드와 같은 정의). 판정은 prereg-S 결정 5의 상대 규칙(|ρ| > 0.3 **이고** 자기 행동 직전 대조군보다 0.10 이상 큼), 고정 규칙(|ρ| > 0.3) 값도 보고.
- 같이 보고: 출처별 값, 칸별 값, 전체 AUROC, 최빈 min_samples_leaf와 fold별 선택, 안쪽 CV 점수, T7-a와의 OOF 점수 순위 상관(Spearman, seed 평균), 찌그러짐 감시값(§2.3).

## 5. 판정 규칙 (미리 정함, 반복 14와 같음)
- **nested 값이 0.90 이상**인 시도가 있으면 맨 앞에 크게 알린다. 그래도 **validation은 열지 않는다**(사용자 결정 대기). test는 봉인 그대로.
- **성공 후보** = TASK.md §0 성공 판정 그대로(`evaluate.success_gate`: nested ≥ 0.90이고 seed마다 ≥ 0.88, family 부트스트랩 CI 하한 ≥ 0.80, 섞기 (a) 0.5±0.05, nested − 섞기 (b) ≥ 0.10, 조정값 nested 선택, 출처마다 ≥ 0.85) + K1 통과 + K3 통과. 감시 검토(조건 6)는 별도. 성공 후보가 나와도 validation 전에 prereg-S 결정 6의 확인(라벨 v1 재측정, 감시 검토 등; 이 구조에는 초기값 seed가 없어 K10 대신 RF random_state 0·1·2 재적합 순위 상관을 잰다)을 거친다. K2(최대 위치 쏠림)·K4(rollout 지름길)는 성공 후보에 대해서만 계산한다.
- **"T7-a보다 낫다"**고 하려면 셋 다: ① T7-a 대비 이득의 95% CI 하한 > 0, ② 섞기 (a) 평균 0.45–0.55, ③ nested − max(자기 섞기 (b), 0.596) ≥ 0.10.
- 행동 직전 대조군이 본 시도와 같거나 높으면 "관측 지점 전체를 쓰는 이득 없음"으로 적는다.
- R0는 비교용이다. R0가 R1보다 높아도 그것만으로 R0를 주 결과로 바꾸지 않는다(둘 다 그대로 보고).

## 6. 지키는 것
- train split만. validation·test 봉인 그대로(evaluate가 train 외 split을 거부한다). 시작할 때 `train_split_only` 검사.
- 실행 중인 S 단계 격자와 반복 14가 쓰는 파일(evaluate.py, within_tool.py, iter06/07_models.py, obs_*.py)은 **고치지 않는다.** 새 코드는 `t7a_rf.py`, `test_t7a_rf.py`에만. 시작할 때 사용 코드 6개의 sha256을 `phase3/rf/start_checks.json`에 남긴다.
- 도구·출처는 **학습 신호로만**(가중치, R2 칸 평균) 쓰고, 학습 위치에서만 읽는다. 점수 함수는 채점 행의 위치와 그 행의 특징만 받는다.
- 누출 감사(하나라도 실패하면 실행을 멈춤): (1) 적합마다 학습·채점 행 겹침 없음, (2) R2의 칸 평균에 실제로 쓰인 행 = 그 적합의 학습 행, 채점 행과 겹침 없음, (3) 시도마다 행동 직전 대조군 포함 각 한 번(fold 0, seed 0), 채점 행의 도구·출처·rollout 정보를 뒤집어도 점수가 **비트 단위로** 같음(메모 저장소를 건너뛰고 직접 계산).
- 합성 데이터 시험(`test_t7a_rf.py`, 13개, 실제 데이터 전): out-of-bag 계산 = sklearn과 같음, 가중치 = 구성원 ①과 같음, RF 입력 = 학습 행으로만 맞춘 robust PCA, **RF 비중 0이면 T7-a와 비트 단위로 같음**(T7-a 부분은 반복 12/14 T7-a와 같음), R0/R1/R2 조합식, **백분위 기준표 = 학습 행(중심화 안 한 특징)만**·평가 행끼리 영향 없음, **R2 중심화가 nested 안쪽 선택까지 학습 행만 씀**, **채점 행 메타데이터 불변**(세 시도 × 대조군), **같은 입력이면 같은 점수**(적합 스레드 1·2 모두), 섞은 라벨이면 점수가 바뀜, sha 검사(DRAFT·불일치·없음이면 멈춤), 축소판 전체 실행·이어하기·보고서.

## 7. 자원·순서·예상 시간
- 시작 조건: S 단계 드라이버가 끝나야(`phase3/s1/ALL_DONE` 또는 `phase3/s1/FAILED`) 시작한다(`phase3/rf/run_rf.cmd`가 2분마다 확인). 작업자 1개, 스레드 2개(RF n_jobs 2, BLAS 2). 남은 RAM이 1 GB 아래면 적합을 멈추고 기다린다(`within_tool.wait_ram`).
- 순서(각 단계가 끝날 때마다 저장, 다시 실행하면 이어서 함): 0) T7-a 재계산 → 1) nested R0 → R1 → R2 → 2) 누출 검사 → 3) 행동 직전 대조군 R0 → R1 → R2 → 4) 섞기 R0 → R1 → R2 → 보고서. 적합 점수는 `phase3/rf/fits/`에 저장되어 R0와 R1이 같은 RF 적합을, R1과 R2가 같은 T7-a 적합을 다시 쓴다.
- **시간 측정(합성, 1회)**: 7,422행 × 42특징, 나무 500개, min_samples_leaf 5, 스레드 2, S 단계가 같이 도는 상태에서 **적합 약 10–14초**, 평가 행 채점 0.1초. 안쪽 학습(약 5,570행)은 더 빠르다.
- 적합 수: nested 한 벌 = seed 3 × 바깥 5 × (안쪽 4 × 격자 3 + 1) = 195 RF 적합. 필요한 RF 묶음: 일반 특징(R0·R1 공유)·중심화 특징(R2) × 전체·행동 직전 = 4벌 ≈ 780 적합. 섞기 = 시도마다 2 × 20 × 5 = 200 적합(R1이 R0와 같은 min_samples_leaf를 고르면 공유) → 400–600 적합. T7-a 적합(로지스틱 3개 + robust PCA) 약 150 + 섞기 200.
- **예상: 약 4–5시간**(RF 적합 평균 8–10초 기준. S 단계가 끝나 CPU가 비면 더 짧을 수 있고, 메모리 대기가 생기면 길어짐). 가장 중요한 숫자(R1 nested)는 시작 뒤 약 1–1.5시간에 나온다.
