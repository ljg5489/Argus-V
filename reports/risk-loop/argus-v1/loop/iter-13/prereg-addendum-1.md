# 사전 등록 부록 1 — 구현 중 빈칸 확정 (2026-11-09, 실제 데이터 실행 전)

`prereg.md`(sha ea354a02…)의 빈칸을 모델 엔지니어가 구현하며 정한 값이다. 실제 데이터로 아무것도 돌리기 전에 오케스트레이터가 그대로 승인·고정한다. sha는 `prereg-addendum-1.sha256`.

1. 동점 처리 순서: 켠 토글 수가 적은 것 → T1→T6 순 → β 작은 것.
2. M0 방향: 로지스틱 C = 0.01 (반복 4 T4-1b 방식).
3. 쌍 가중: 쌍마다 1 (prereg 문구대로).
4. T6 가중은 BCE와 쌍 손실 모두에 적용(쌍 가중 = 두 행 가중의 곱).
5. T3 보조 손실: 보고 도구 행의 클래스 균형 BCE. T1 focal은 보조 손실에 적용하지 않음.
6. T2 잡음: 8조각 가우스 뱅크를 epoch마다 재배열(값은 정확한 가우스).
7. nested 단계: 초기값 seed 1개(선별 단계 적합 재사용).
8. 확인 단계: β는 안쪽 CV-4로 고름.
9. 고정 섞기 20회: nested가 가장 많이 고른 (조합, β), 보조 라벨도 함께 섞음.
10. 선택까지 다시 하는 섞기 (b) 5회: **fold seed 0만**(계산량 때문, 3 seed면 약 7.2만 회). 결과에 이 한정을 표시한다.
11. K11 캐시 충실도 검사는 데이터 엔지니어의 `k11_cache_check.py`를 공식으로 쓰고, `obs_grid.py k11`은 보조로 함께 보고.
12. 계산 시간이 길면(예상 13~27시간) 순서대로: 확인 단계 초기값 seed 3→1, 그다음 병렬 수 조정. 그 외 축소는 새 부록 없이는 하지 않는다.
