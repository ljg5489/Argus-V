# 라운드 3 — 평가·검증 담당: 인정·반박, 고친 사전 등록

작성 2026-11-09. 계산 실험 없음. 조회: `iter-11/nov_review_14.csv`(14행 모두 "사용자 결정 2026-11-08"), `iter-12/data_plan.md:238`(관례 반영 뒤 칸 9개·위반 49개), `LOOP_LEDGER.md` 12a(T7-a 0.721). 정정: **`dec` 별도 출처 + 사람 검수 행만 판정**은 사용자 결정(2026-11-08)이다. r1에서 "오케스트레이터 결정"처럼 쓴 부분을 바로잡는다. 캡처는 사용자 결정 `--observe-every 8 --layers all`.

## 1. 인정·반박 (망나니 r2 §5 질문 순서)
- **(1) K=32 버림 → 인정.** K=4로 고정(격자 아님). 근거: 판정 위반 49~180개, T7-c MLP 0.550. 격자는 W의 L2 3값 × epoch만 남는다.
- **(2) PCA 512 투영 캐시면 계산이 작아진다 → 인정.** 다시 잰 계산은 §5. 1회 학습이 몇 분에서 몇 초로 줄고, RAM 문제도 사라진다.
- **(3) "사람 검수만"이면 지금 칸은 몇 개가 되나.** 사용자 결정은 **새 `dec` 데이터에 대한 것**으로 읽는다. 그러면 oct·nov 판정은 지금(12a 관례 반영) 그대로 **칸 9개·위반 49개**다. 참고로 oct·nov까지 엄격하게 적용하면(정상 행까지 사람 검수 요구) 11월 칸의 정상 행은 대부분 초안이라 11월 칸 2개가 빠지고, 남는 것은 10월 칸 약 7개·위반 약 38개다(추정이고 10월 위임 판정을 사람 확인으로 볼지는 확인 못 함). 엄격판은 참고로만 보고하고, 범위는 사용자에게 한 줄로 확인을 받는다.
  - `dec`에서는 **정상 행도 사람 검수**를 받아야 판정에 들어간다(`label_status=dec_reviewed`, 라벨 값과 무관). 판정 칸 도구의 행은 **전수 검수, 또는 미리 정한 seed로 무작위 검수**한다. 모델 점수로 고른 행(능동 선택)은 학습에만 쓴다(r2 지적 인정).
- **(4) 32 격자 솎기를 v5에 넣나 → 반만.** 솎기 자체는 특징을 만드는 일이라 `build_features.py`에서 한다(시험 포함). v5 평가 코드는 **확인만** 한다. `dec` 행이 하나라도 `n_obs ≠ n_obs_32`이면 `ValueError`를 낸다. 합성 시험 2개를 더한다(솎지 않은 행 거부, 솎은 행 통과).
- **(5) K1을 seed 0~2로 먼저 싸게 돌리기 → 동의, 조건 하나.** 앞단 결과는 **끝내는 데만** 쓴다. 설정을 고치거나 다음 단계로 넘기는 근거로는 쓰지 않는다. 앞단에서 보는 것은 시도 수에 이미 들어간 모델뿐이다.
- **반박 1 — PCA 기저 범위.** r2는 "봉인 제외 전체"로 512 기저를 맞추자고 했다. 나는 **train 행, 그중 32 격자 행만**을 주장한다. 라벨이 없어도 validation 행이 기저를 움직이면 validation이 단 1회 보기가 아니게 된다. 비용 차이는 없다.
- **반박 2 — K6.** 25%와 50%가 거의 같았던 T7-a 곡선(D3)을 보면, 점 3개로 기울기를 비교하는 것은 잡음이다. 노선을 끝내는 기준이 아니라 **"데이터가 늘면 이긴다"는 주장만 막는 기준**으로 둔다.

## 2. 고친 사전 등록 (`iter-13/prereg.md`로 옮겨 sha 고정; 새 텐서를 받기 전에)
공통: 32 격자(`dec`는 솎음). 층 20. 견고 척도 → PCA 512(train 32 격자 행, 라벨 없음) → fold 안 PCA 32. 관측 종류·도구·출처는 입력에 넣지 않는다. 같은 fold·같은 행·평가 v5.
| 이름 | 정의 | 자유 파라미터 | 시험하는 것 |
|---|---|---|---|
| **M0** | fold 안 층 20 pre_action 행으로 쌍 로지스틱 방향 w를 학습 → 모든 관측에 대어 [max, mean, pre_action] → 로지스틱 머리 | 약 4(+w 32) | 추론 중간 행의 max가 행동 직전 하나보다 정보를 더하나 |
| **M1** | W∈ℝ^{32×4}(초기값 = M0의 w + 작은 잡음) → 필터별 하드 max·mean 8개 → 선형 머리. 손실 = 같은 rollout 쌍 손실 + 0.2·점별 BCE. 관측 dropout 0.25. L2 ∈ {1e-3, 1e-2, 1e-1}·epoch는 안쪽 CV로 고름 | 약 140 | 학습된 투영 → max |
| C-pre | M1과 같은 W 구조, 입력은 pre_action 행 하나(풀링 없음) | 약 136 | 대조: 풀링이 장식인가 |
| C-cmax | 층 20 좌표별 max → 같은 전처리 → 로지스틱 | 33 | 대조: 학습된 투영 vs 원래 좌표 max |
| T7-a | 현재 최고(층 23 max·층 16 pre, 기존 코드 그대로) | 고정 | 넘어야 할 기준 |
| R-only | trajectory 평균 특징 로지스틱(진단 0.678) | — | rollout 지름길의 크기 |
- seed: 판정에 fold seed 0~9, M1은 fold마다 초기화 seed 3개 평균이 곧 "모델 1개". 섞기 (a)(b)는 각 20회(fold seed 0, 가장 자주 고른 L2·epoch로 고정, 초기화 1개). (b)는 3회만 안쪽 선택까지 다시 돌려 비교한다.
- 추가 대조: (c) 관측 순서 섞기(점수가 그대로여야 함, 다르면 버그), (d) pre_action 빼기.
- 시도 수: M0, M1, 대안 1개 = 3. 누적 68 → 최대 71. 8 격자 `dec` 내부 분석은 시도로 세고 판정에는 쓰지 않는다.
- 보고: 판정 지표(v5 · v4 나란히), 출처별, 보조 지표 C(같은 trajectory·같은 도구 순위), argmax 종류 분포, n_obs_32 상관, 짝 bootstrap 차이(M1−C-pre, M1−C-cmax, M1−T7-a).

## 3. 중단 기준 — 망나니 8개를 채택하고 고친 부분
- **K1** M1(또는 M0) − C-pre: 앞단(seed 0~2) 점 추정 ≤ 0이면 종료. 본판은 seed 0~9 짝 bootstrap 95% CI 하한 ≤ 0이면 종료.
- **K2** 위반 step argmax의 80% 이상이 pre_action+reasoning_end면 종료. 필터별 비율에 머리 계수 |β|로 가중한다. 우연 기준(2/n_obs_32, 평균 약 25%)도 함께 적는다.
- **K3** 칸 안 |Spearman(점수, n_obs_32)| > 0.3이고 **C-pre보다 0.10 이상 크면** 종료(길이 자체가 위험과 엮였을 수 있어 대조와 비교한다). dropout을 키운 변형 1회만 허용.
- **K4** 그대로: C − max(자기 섞기 (b), 0.5) < 0.10. 더해서 C ≤ R-only의 C 값이면 종료.
- **K5** M1 − T7-a 점 추정 < +0.03이면 채택하지 않는다(노선은 K7까지 갈 수 있다).
- **K6** 고침: 노선 종료가 아니라 "데이터가 늘면 이긴다" 주장 금지(§1 반박 2).
- **K7** 그대로: `dec` 사람 검수 칸으로 확인 1회, M1 ≤ T7-a(10 seed 점 추정)면 종료. 고치기 금지.
- **K8** 고침: 50 step은 뒤집힘 1개가 2%라 너무 작다. **200 step 이상**, 점수 Spearman ≥ 0.99, 판정 뒤집힘 ≤ 2%(95% 상한)를 요구한다. 못 넘으면 "실시간 차단" 주장 보류(정확도 판정과는 별개).
- **K9(추가, 파이프라인 오류)** 섞기 (a) 평균이 0.45~0.55를 벗어나거나 (c)에서 점수가 바뀌면 결과 무효 → 버그부터 고친다(시도 수 그대로).
- **K10(추가)** 초기화 seed 3개 점수의 순위 상관 중앙값 < 0.8이면 M1은 불안정 → M0만 남긴다.

## 4. 8 대 32 토큰 밀도
- **판정·출처를 섞는 학습과 평가는 모두 32 격자를 쓴다.** `dec`는 j=4k+3 행과 pre_reasoning·reasoning_end·pre_action만 남긴다. 8 격자는 32 격자를 정확히 포함한다(r2 §1). 이유: max 극값 효과(n=8 → 25에서 +0.55σ)가 출처와 함께 움직인다. v3 때의 출처 지름길이 다시 생긴다.
- 8 격자는 `dec` 안에서 보고만 한다. (i) 같은 모델로 8 격자와 32 격자 점수의 Spearman(밀도 민감도), (ii) argmax 위치를 더 잘게 짚기(해석), (iii) `dec`만으로 8 격자 학습 1회(시도로 셈). 이것이 판정을 대신하지 못한다.
- 배포 hook은 8 격자로 캡처하더라도 **scorer가 32 격자로 솎은 뒤 점수를 낸다**. 학습한 밀도와 같아야 문턱이 맞는다. 밀도를 바꾸려면 재학습과 재평가가 필요하다.

## 5. 계산 예산 (18코어, RAM 15.5GB, PCA 512 캐시 기준; 추정)
- 입력: train 32 격자 행 약 13만(옛 데이터 step 약 1.6만 × 8.1) + `dec` 솎은 행. 층 20 512차원 fp16 ≈ 0.2GB, fold 안 PCA 32 뒤에는 약 17MB. 작업 9개가 각자 들고 있어도 2GB 아래다.
- 1회 학습: fold 안 PCA 32 약 1~2초 + M1(약 140 파라미터, 전체 배치 Adam 300 step, `scatter_reduce` max) 약 1~3초 → **약 2~5초**(1~2스레드). M0·C-cmax·C-pre는 1초 미만, T7-a는 기존 비용.
- 본판(M1): 10 seed × 5 바깥 × (3 안쪽 × 3 L2 + 1) × 초기화 3 = 1,500회. 섞기 40 × 5 = 200회. (b) 재선택 3 × 5 × 10 = 150회. 대조 (c)(d) 약 100회. M0·C-pre·C-cmax·R-only의 본판·섞기 약 1,200회(빠름). **합계 약 3,200회 × 평균 3초 ≈ 2.7 CPU-시간 → 작업 9개 병렬로 약 20~30분.** bootstrap 2,000회 × 모델 6개는 수 분.
- 앞단(K1, seed 0~2, 섞기 없음): 약 5분. 진짜 비용은 학습이 아니라 **캐시 만들기**다(HF 원본 약 25~30GiB 전송, 시스템 담당 추정 범위). r1의 10~25시간은 철회한다(원본 2880차원 가정).

## 6. 추론 데모 인수 시험 (성능과 무관하게 납품, "후보 아님" 표시)
시스템 담당의 `ArgusScorer`(`score_step`, `start/update/finalize`)와 `infer_demo.py`가 아래를 모두 통과해야 한다.
1. 저장물 1개: 견고 척도 통계, PCA 512·32 기저, W, 머리, 보정, 문턱, 학습 행 hash, 코드 sha, 학습 밀도(=32).
2. 학습은 바깥 fold 4개의 family로만 한다. 데모 입력은 **남긴 fold의 train step**을 HF 원본 `features.npz`에서 직접 읽는다(옛 32 격자 1개 단위, `dec` 8 격자 1개 단위). 서명에 도구·출처·라벨 인자는 없다.
3. 출력: 보정 점수, 학습 분포 백분위, 필터별 최고 관측(index·kind·token_index), 차단/통과 판정, 그 지점의 추론 문장 32토큰 창.
4. 문턱·보정은 안쪽 OOF로만 정한다(정상의 95백분위 = 거짓 경보 5% 목표). 남긴 fold에서 실제 재현율·거짓 경보율을 CI와 함께 보고한다.
5. 일치: `score_step` = 평가 파이프라인 OOF 점수(차이 < 1e-4). 스트리밍 `finalize` = `score_step`(비트 일치). 8 격자 입력은 scorer 안에서 솎은 결과 = 미리 솎은 캐시 결과.
6. 견고성: n_obs=1(pre_action만) 처리, 블록 누락·모양 오류·fp16 넘침이면 명확한 오류. step당 지연과 메모리를 보고한다.
7. validation은 쓰지 않는다. validation은 성공 판정 1~6(감시 감사 포함)을 통과한 후보만 1회 연다. 0.90 미달 모델의 validation을 열지는 사용자가 정한다.
