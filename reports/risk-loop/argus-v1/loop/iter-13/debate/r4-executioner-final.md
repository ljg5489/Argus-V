## 1. 라운드 3 답변 평가
**설계자** — 질문 5개에 정직하게 답했다(P1 8.3k·A2·τ·관측 종류 바이어스·m − g·층 11 철회, KV 불일치 누락 인정). 쓸 만한 새 제안 둘: 필터 bias는 머리 절편과 겹쳐 식별 불가(맞음), pre_action 항을 넣어 C-pre를 포함하는 중첩 모델로 만들기(맞음, 채택). 층 20 반박도 맞다(D2 0.865는 48개 중 고른 "중심 거리·추론 끝"이고 max가 아니다). 새 오류: (가) 그가 추가한 "K9"(머리 계수 |v_max|+|v_mean| < 10%·|v_pre|)는 특징 척도에 따라 달라지고, max·mean·pre가 서로 강하게 상관돼 계수가 흔들린다 → 기각, 표준화 계수는 진단으로만. (나) "M2는 새 데이터 도착 뒤 M2 − M1′로 승격"은 평가 담당의 "dec 전에 잠금, dec는 1회 확인"과 충돌 → M2 결정은 지금 데이터에서 끝낸다.
**학습 전략가** — 정직하다("최악 ≈ T7-a", LEACE, 쌍둥이 최대 가중, 사전학습 모두 철회). 새 약점: (가) 초기화 w₂(모든 행이 라벨 상속)·w₃·w₄(차이 벡터 PCA)는 라벨을 쓰는 설계 선택 3개를 새로 더한다. (나) 쌍 손실에 "같은 칸·다른 rollout 쌍 1.0"을 넣었다. 이는 rollout 수준 신호가 다시 들어오는 통로이고 다른 세 사람의 M1에는 없다. (다) "pre_action도 dropout으로 빠질 수 있음"은 pre_action 항이 있는 M1′와 양립 불가. (라) bias b_k를 남겼다(식별 불가). (마) β와 epoch(최대 300)를 둘 다 안쪽 CV로 고르면 서로 얽힌 손잡이 2개다. (바) K3 변형 "dropout 0.5"는 학습만 바꾸고 추론 때의 길이 의존은 그대로다. 쌍둥이 20~50쌍 추정은 X 정상 수율 가정이 확인 안 됨.
**평가 담당** — 정직하다(K=32 철회, 10~25시간 철회, 사용자 결정 출처 정정). 개선점: K3를 C-pre와 비교하게 고침, K8을 200 step으로 키움, 앞단 결과는 끝내는 데만 쓰기, PCA 기저를 train 행으로만 맞추기. 새 약점: (가) M1 초기값 "M0의 w + 작은 잡음"을 4열 모두에 주면 필터가 대칭으로 붙어 사실상 K=1이 된다. (나) K8 "뒤집힘 95% 상한 ≤ 2%"는 200 step에서 뒤집힘 0~1개라는 뜻이다. 명시해야 한다. (다) 데모의 "`dec` 8 격자 단위"는 지금 없다. (라) K9·K10 번호가 설계자 K9와 겹친다 → 아래 최종 번호로 통일.
**시스템 담당** — 정직하다(9층·K 16~64·"가장 안전" 철회). 이번 토론에서 가장 값진 새 발견: 출력 폴더에 32 간격 rollout이 있으면 건너뛰어져 간격이 섞인다(코드 확인). 새 오류: (가) 캐시 2회차를 "dec 업로드 뒤 한 번에"로 미뤘다 → 지금 데이터 작업이 전부 막힌다. 옛 단위와 `dec`는 다른 단위라 따로 받아도 전송량이 같다. 옛 데이터는 지금 만든다. (나) "PCA 512 설명 분산 ≥ 95%"는 대리 지표일 뿐이다. 정보 보존은 실제 점수로 재야 한다(K11). (다) K8 50 step은 평가 담당의 200으로 대체.

## 2. 남은 충돌 정리
| 쟁점 | 결정 | 이유 |
|---|---|---|
| M1(max+mean) vs M1′(+pre_action) | **M1′** | C-pre가 M1′ 안에 포함돼 K1이 "풀링만의 이득"을 깨끗하게 잰다 |
| W₀ 초기화 | 1열 = M0의 w, 2~4열 = N(0, 0.01²), 벌점 기준 = (w, 0, 0, 0) | 새 선택이 가장 적다. 대칭 붕괴가 없다. M1′은 데이터가 값을 치를 때만 M0에서 멀어진다 |
| 학습 손잡이 | β만 안쪽 CV {0.1, 1, 10}. epoch 200 고정(수렴 확인) | L2-SP 목적함수는 최소점이 정해져 있어 조기 종료가 중복이다. iter-05: 고르는 것만으로 안쪽 0.67 → 바깥 0.54 |
| 설계자 K9 vs 평가 K9·K10 | 계수 규칙 기각. 평가의 파이프라인 유효성·초기화 안정성 채택(번호 재부여) | 위 1절 |
| 일치 기준 1e-4 vs 1e-3 | 둘 다, 대상을 나눔: 캐시 fp16-512 입력 → OOF ≤ 1e-5. HF 원본 fp32 입력 → OOF ≤ 1e-3, 그리고 문턱 ±1e-3 밖 판정 100% 일치 | 차이의 원인은 fp16 반올림뿐이다 |
| 캐시 층 {20} vs {16,20,23} | **{16, 20, 23}** | 전송량이 같고 층당 0.13GB다. M2(층 23)·T4-1b 계열(층 16)에 필요하다 |
| PCA 512 기저 범위 | **옛 train 단위의 32 격자 행만**. `dec` 도착 전에 sha 고정 | validation이 기저에 안 섞인다. 새 데이터 보기 전 잠금 |
| 검수 행 선택 | `review_selection ∈ {census, random, active}`. 판정 칸 도구 행은 census(전수), 남는 예산은 seed 고정 random, active는 학습 전용 | 모델이 판정 집합을 고르지 못하게 |
| K3 걸릴 때 1회 변형 | **상위 2개 평균** 풀링 | 추론 때의 점수 함수 자체를 바꾸는 쪽이어야 한다(dropout 0.5는 아님) |
| 쌍 종류 | 같은 rollout 쌍만(같은 도구 1.0, 다른 도구 0.3, 위반당 가중 합 1) | 다른 rollout 쌍(쌍둥이 포함)은 평가 보조 지표로만 |

## 3. 사전 등록할 최종 설계 (`iter-13/prereg.md`, dec 텐서 받기 전 sha 고정)
**입력(공통)**: 층 L 관측 행 x_i ∈ ℝ^2880. 32 격자만 쓴다(8 간격 단위는 `reasoning+N`에서 N%32==0만 남김). n ∈ [1, 64]. 관측 종류·도구·출처·step 번호는 입력 금지(종류는 설명 기록용).
**고정 전처리(라벨 없음)**: x̃ = clip((x − med_L)/(IQR_L/1.349), ±3) → u = P₅₁₂ᵀ(x̃ − μ_L) ∈ ℝ^512(캐시 값) → fold 안 PCA 32 + 표준화 → z_i ∈ ℝ^32.
- **M0 (시도 1)**: fold 안 층 20 pre_action 행으로 같은 rollout 쌍 로지스틱 → w ∈ ℝ^32. g_i = wᵀz_i → f = [max_i g, mean_i g, g_pre] → 로지스틱 머리(4). 자유 파라미터 32 + 4.
- **M1′ (시도 2, 주 모델)**: 층 20. h_i = Wᵀz_i, W ∈ ℝ^{32×4}(bias 없음). f = [max_i h; mean_i h; h_pre] ∈ ℝ^12. s = vᵀf + c. **파라미터 141.** 손실 L = L_pair + 0.2·BCE_w + β‖W − W₀‖²_F + 0.01‖v‖². L_pair = 같은 trajectory (위반, 정상) 쌍 softplus(−(s_a − s_b)), 위 표의 가중치. BCE_w = 출처×클래스 가중(H2-1c와 같음). `dec` 규칙 라벨 행은 학습에만 0.8/0.99(사용자 결정 U3). 관측 dropout 0.25(pre_action 행은 빼지 않음, 최소 1행). Adam lr 1e-2, 전체 배치, 200 epoch. 초기화 seed 3개 점수 평균 = 모델 1개.
- **시도 3 (둘 중 하나, 순서 고정)**: K3가 M1′에서 걸리면 → 상위 2개 평균 변형. 아니면 → **M2**: 층 {20, 23} 각각 PCA 32·K=4 → f ∈ ℝ^24, 파라미터 281. **M2 관문**: 지금 데이터 seed 0~9에서 M2 − M1′ 짝 bootstrap CI 하한 > 0이고 K1~K4·K10 통과 → M2를 잠금 모델로. 아니면 M1′을 잠근다. dec 전에 결정한다.
**대조(시도 수에 안 셈)**: C-pre(M1′ 구조, pre_action 행 하나), C-cmax(층 20 좌표별 max → 로지스틱), T7-a(기존 코드), R-only(trajectory 평균), 평가 코드 내장 기준선(길이+step, n_obs_32, 도구 이름). 추가 대조: 관측 순서 섞기, pre_action 빼기.
**seed**: 앞단 fold seed 0~2(끝내는 데만), 판정 0~9. 섞기 (a)(b) 각 20회(seed 0, 가장 자주 고른 β 고정), (b) 3회는 안쪽 선택까지 다시. 누적 시도 68 → 최대 71.
**밀도**: 출처를 섞는 학습·평가는 모두 32 격자. 8 간격은 `dec` 안 **진단만**(잠긴 모델로 8 대 32 점수 Spearman, argmax 위치 세분화). 학습은 하지 않는다 → 시도 아님. scorer는 배포 때도 32 격자로 솎는다.
**캐시(TASK.md:44·48 안)**: 1회차 = 옛 train row group 30%에서 32 격자 행 2만 개로 med/IQR·PCA 512 적합(RAM만), `basis_L{16,20,23}.npz` sha 고정. 2회차 = 옛 train·val 전체 투영 → `obs512_L{16,20,23}.npy` fp16 + `obs_offsets.npy` + `obs_index.csv`(`on_grid32`, kind, token_index). 옛 0.39GB + dec 0.21GB → 기존 2.04GiB와 합쳐 약 2.64GB(≤ 3GB). 원본 2880 행은 디스크에 안 씀.
**중단 기준(최종 번호)**
1. K1 풀링 장식: M1′ − C-pre가 앞단 점 추정 ≤ 0, 또는 seed 0~9 짝 bootstrap 95% CI 하한 ≤ 0 → 종료(M0도 같은 규칙, 자기 C-pre와 비교).
2. K2 퇴화: 위반 step argmax(머리 |계수| 가중)의 80% 이상이 pre_action+reasoning_end → 종료(우연 기준 2/n_obs_32 같이 보고).
3. K3 길이: 칸 안 |Spearman(점수, n_obs_32)| > 0.3이고 C-pre보다 0.10 이상 크면 → 상위 2개 변형 1회, 다시 걸리면 종료.
4. K4 rollout 지름길: 보조 지표 C − max(자기 섞기 (b), 0.5) < 0.10, 또는 C ≤ R-only의 C → 종료.
5. K5 채택: 잠금 모델 − T7-a 점 추정 < +0.03이면 채택 안 함(노선은 K7까지).
6. K6 학습 곡선: 기울기가 T7-a(2배당 +0.06)보다 크지 않으면 "데이터 늘면 이긴다" 주장 금지(종료 아님).
7. K7 dec 확인 1회: 잠금 모델 ≤ T7-a(10 seed 점 추정) → 종료. 고치기 금지.
8. K8 배포 일치: 4090 KV 경로 vs 재실행 ≥ 200 step, 점수 Spearman ≥ 0.99, 판정 뒤집힘 ≤ 1개(95% 상한 ≈ 2%) → 아니면 "실시간 차단" 주장 보류.
9. K9 파이프라인 유효성: 섞기 (a) 평균이 0.45~0.55 밖이거나 순서 섞기에서 점수가 바뀜 → 결과 무효, 버그 수정(시도 수 그대로).
10. K10 초기화 안정성: seed 3개 점수 순위 상관 중앙값 < 0.8 → M1′ 버리고 M0만.
11. K11 캐시 충실도: 층 20·16의 pre_action 행 쌍 로지스틱을 512 투영 입력 vs 기존 원본 캐시(`L20_pre`, `L16_pre`)로 돌렸을 때 판정 지표 차이 > 0.01 → 사용자에게 예외 요청(U4).
**추론 패키지(성능과 무관하게 납품, `"candidate": false`)**: `argus_v1_pool.safetensors`(med, IQR, clip, 접은 투영 W_eff[K,2880] = (P₅₁₂·Q·S·W)ᵀ, b_eff, 머리, 백분위 보정표) + `.json`(층, 학습 밀도 32, K, 문턱, HF revision, 학습 단위 hash, 커밋). API: `score_step(obs:{L:[n,2880]}, kinds)`, `start/update/finalize`(상태 = 필터별 max·합·argmax, 개수, pre). 도구·출처 인자 없음. 출력 = 점수, 백분위, 차단/통과(문턱 = 안쪽 OOF 정상의 95백분위), 기여가 가장 큰 필터의 argmax 관측(kind, token_index) + 그 앞 32토큰 추론 문장.
**인수 시험**: (1) 스트리밍 = 일괄 계산(비트 단위), (2) 위 2절 일치 기준 2개, (3) n_obs=1·`reasoning_end` 없음·8 간격 입력 자동 솎기·블록 누락·모양 오류·fp16 넘침 처리, (4) 남긴 fold의 train 단위를 HF 원본에서 직접 읽어 `infer_demo.py`로 재현율·거짓 경보율(CI) 보고, (5) 봉인 단위 거부, (6) 온라인 harmony 파서가 저장된 `token_pieces`로 오프라인 관측 위치와 100% 일치. 이것이 "hook 텐서 → 점수·판정·근거 위치"를 끝까지 잇는 모델이다. 가벼운 것은 학습되는 부분뿐이고, 그 크기는 위반 수가 정한다(작은 MLP T7-c 0.550).

## 4. 만드는 순서
**지금(4090 데이터 전, 이 PC)**
1. `prereg.md` 작성·sha 고정(위 3절 전부, 검수 선택 규칙 포함).
2. `build_features.py` `observe_every`·`grid32_mask`·`n_obs_32` + 시험 3개(시스템 §3). 평가 v5(`dec` 출처, `n_obs ≠ n_obs_32` 거부, 합성 시험) sha 고정.
3. `pilot_capture_check.py`를 만들어 사용자에게 넘김(폴더 비었는지, `observe_every==8`, 행 수, 크기·시간, |값| 최댓값).
4. 캐시 1회차(기저 sha 고정) → 2회차(옛 데이터, 약 17GiB·65분) → K11.
5. `ArgusScorer` + `infer_demo.py` 배관 모드 + 파서 시험.
6. 대조·T7-a 재현 → M0 → M1′ 앞단(K1) → 판정 묶음 → 시도 3(K3 변형 또는 M2 관문) → 모델 잠금.
7. 잠금 모델을 train 전체로 맞춰 패키지(`candidate: false`), 데모 실행. `kv_parity_check.py`는 작은 임의 모델로 CPU 단위 시험까지.
**4090 데이터 뒤**
8. pilot 확인(4090: 출력 폴더 비었는지, `PYTHONUTF8=1`, 항목 ①③⑥) → 본 실행 → 업로드.
9. 고정 기저로 `dec` 투영 추가, 항목 ②④⑤.
10. 판정 칸 도구 census + random 검수(`review_selection` 기록).
11. 잠긴 코드로 `dec` 포함 확인 실행 1회(K7). 12. 4090 KV 일치 ≥ 200 step(K8) → `argus_guard.py` 실시간 판정.

## 5. 사용자가 정할 것
- **U1 "판정 = 사람 검수 행만"의 범위**: 평가 담당 권고 = `dec`에만(oct·nov는 지금 규칙, 칸 9개·위반 49개). 엄격판(oct·nov도)은 칸 약 7개·위반 약 38개로 줄어든다(추정) → 참고로만 보고. 저도 `dec`만에 동의한다.
- **U2** 10월 "위임 판정" 행을 사람 확인으로 볼지(엄격판에만 영향).
