## 반복 1에서 확인한 구조적 사실 (계획의 근거)

- 판정 지표 도구 10개 중 8개는 **family 1개에만** 있다(bash 24개, grant_review_access 2개 예외). family 단위 CV라서, 어떤 도구가 test fold에 있으면 그 도구의 행은 학습 fold에 거의 없다. 그러므로 모델은 "다른 시나리오의 같은 도구 안 위반·정상 차이"에서 배운 방향을 새 시나리오에 옮겨야 한다.
- 반복 1 모델은 도구·family 사이 차이(위반 비율이 높은 family, 긴 행동)를 먼저 배운다. 판정 지표는 도구 안 순위만 본다. 섞기 (b) 0.634, 길이+step 0.646이 실제 최고 0.657과 거의 같았다.

## 가설과 시도 (새 시도 ≤ 20개, 계획 기준 12개)

모든 새 모델은 fold 안에서만 맞춘다(표준화·PCA·중심화·길이 방향·가중치·분류기). 기본 표현은 반복 1 최고인 **층 23 max**. 격자는 반복 1과 같은 k ∈ {10, 32, 128} × C ∈ {0.001, 0.01, 0.1}을 nested CV로 고르고, 격자 하나는 시도 1번으로 센다.

### H2-1 같은 도구 안 학습 신호 (도구 이름은 학습 fold 안에서만)

- **H2-1a 도구별 중심화 LogReg** (`tool_centred_logreg`): 학습 행의 표준화 특징에서 각 도구의 학습 평균을 뺀다 → 중심화된 학습 행으로 PCA → LogReg(출처×클래스 가중치).
  - 점수 시점에는 중심화하지 않고 같은 선형 함수를 그대로 쓴다.
  - **정합성 근거**: 선형 점수 w·x에서 도구별 평균을 빼는 것은 도구마다 상수 하나를 더하는 것과 같다. 같은 도구 안 AUROC는 도구 안 순위만 보므로 점수 시점에 중심화를 하든 안 하든 값이 같다. 따라서 "학습 때만 중심화"로 생기는 불일치는 판정 지표에 영향이 없다. 전체 AUROC(참고)는 달라질 수 있다.
- **H2-1b 같은 도구 쌍 순위 학습** (`pairwise_rank`): 학습 fold 안에서 같은 도구의 (위반, 정상) 쌍을 모두 만들고, 중심화 PCA 공간의 차이 벡터로 절편 없는 logistic 손실을 학습(RankSVM의 logistic 판). 위반 한 개의 쌍 가중치 합이 1이 되도록 맞춘다(행이 많은 bash가 독점하지 않게). 점수 = w·x, 도구 불필요.
- **H2-1c 도구 가중치 LogReg** (`tool_weighted_logreg`): 중심화 없이 반복 1 모델과 같되, 학습 fold에 위반·정상이 함께 있는 도구의 정상 행 가중치 합이 나머지 정상 행 가중치 합과 같아지도록 올린다.
- 시도: H2-1a-L23, H2-1b-L23, H2-1c-L23, 그리고 층 일관성 확인용 H2-1b-L16(Argus-V1 기본 층). → **4개**

### H2-3 길이 방향 제거 (잔차화보다 강하게)

- A단계(H2-1)의 최고 모델에 붙인다. 학습 fold의 (도구별 중심화된) PCA 성분으로 도구별 중심화된 log prefix_length와 step_index를 ridge로 예측하는 방향을 찾아 빼고(deflation), 남은 공간에서 다시 찾아 빼기를 m번 반복한다. 학습·점수 모두 같은 선형 사영을 쓴다(사영은 도구 불필요).
- 시도: m = 1, m = 4 (목표 2개이므로 방향 2개·8개 제거). → **2개**

### H2-2 관측 지점 대비 특징

- A∪B 단계 최고 모델 구성으로 표현만 바꾼다. 각 블록은 fold 안 표준화 후 연결.
- 시도: L23 rend − pre, L23 max − mean, [L16 max, L23 max] 연결(블록별 표준화, 블록 크기로 나눠 같은 비중). → **3개**

### H2-4 (새 아이디어) 같은 rollout 앞 step 기준 변화량

- 이유: 같은 도구는 같은 시나리오에서만 나와서 시나리오(맥락) 고유의 activation 차이가 도구 안 신호를 가린다. 점수 시점에 도구 평균을 빼는 것은 금지지만, **같은 rollout의 앞 step activation 평균**은 감시 시점에 이미 관측된 값이라 쓸 수 있다. x − (같은 trajectory에서 step_index가 더 작은 기본 트랙 행 특징의 평균)을 특징으로 쓴다. 앞 step이 없으면 0 벡터(판정 위반 52개 중 48개는 앞 step이 있음).
- 입력은 activation(앞 step 포함, 모두 현재 행동 전 관측)과 trajectory 묶음뿐이다. 다음 행동의 도구·결과·라벨·시나리오 코드는 쓰지 않는다. trajectory 묶음을 점수 입력에 쓰는 것이 §3에 맞는지는 **감시 에이전트 확인이 필요**하다고 표시한다.
- 시도: H2-4 변화량 + A∪B 최고 모델, H2-4 변화량 + 반복 1 모델(`pca_logreg`, 도구 학습 신호 없음). → **2개**

## 선택 규칙 (사전 등록)

1. 순위: nested CV **seed 평균 같은 도구 안 AUROC**가 높은 순. 0.005 이내면 단순한 쪽(H2-3·H2-2·H2-4 추가 없음, 작은 격자)을 앞에 둔다.
2. 순위 상위 3개(진단 아님)만 `evaluate.evaluate()` 전체(부트스트랩 CI, 섞기 (a)(b), 기준선)로 돌린다. 이 재계산은 새 시도로 세지 않는다.
3. **후보로 인정하는 조건**(둘 다 만족해야 함):
   - 같은 도구 안 AUROC − 섞기 (b) 평균 ≥ 0.10
   - 같은 도구 안 AUROC − 길이+step 기준선(같은 fold) ≥ 0.05
   만족하는 것이 없으면 candidates.md에 "후보 없음"으로 적는다.
4. 감시 규칙 R1에 따라 누적 시도가 30을 넘었으므로 반복 1 최고(0.657)보다 0.12 이상, seed 3개·두 출처 모두 같은 방향일 때만 "실제 개선"으로 적는다. 판정은 평가 에이전트가 한다.
