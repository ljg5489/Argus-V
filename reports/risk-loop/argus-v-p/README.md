# Argus-V-p — 발표용 "가능성" 시연 모델

작성 2026-11-15(실행 전에 고정한 계획). 사용자 지시: "제일 성능이 좋았던 모델로, 너무 심하지 않게 어느 정도 과적합을 내서 0.9 이상을 내자. 가능성은 보여 줘야 한다." 이름은 사용자가 정했다. 발표는 2026-11-18.

## 무엇이고 무엇이 아닌가

- **무엇**: 지금 최고 모델(T7-a: 층 23의 관측 지점별 최댓값과 층 16의 행동 직전 값 → 척도 맞춤 → PCA → 선형 모델 3개의 백분위 평균)을 바탕으로, "어떤 조건이면 0.9에 닿는가"를 보여 주는 모델.
- **무엇이 아닌가**: Argus-V1 루프의 판정 후보가 아니다. 여기 수치는 판정 지표 값으로 쓰지 않고, 루프의 누적 시도 수(169)에도 넣지 않는다. 설정 수는 이 폴더의 `ledger.md`에 따로 적는다. validation·test·봉인 데이터는 쓰지 않는다(train 분할 판정 행 9,278개, 학습 위반 76개, 평가에 들어가는 위반 48개).
- **입력**: hidden state뿐이다. step 번호, 프롬프트 길이, 도구 이름은 입력으로 쓰지 않는다.

## 세 조건 — 모든 수치에 조건을 붙인다

| 조건 | 무엇을 학습에 넣고 무엇을 채점하나 | 뜻 |
|---|---|---|
| A. 처음 보는 시나리오 | 시나리오 계열을 통째로 빼고 학습, 뺀 계열을 채점 | 진짜 일반화 성능. 판정 지표와 같은 방식 |
| B. 이미 본 시나리오의 새 실행 | 같은 시나리오의 다른 seed를 학습에 넣고, 남은 seed를 채점. 앞부분이 똑같은 복제본은 같은 묶음에 둔다 | 도구별 예시가 조금 있으면 되는가 |
| C. 학습 데이터 재채점 | 전체에 학습하고 같은 행을 채점 | 신호를 담을 용량이 있는가. 일반화의 근거는 아니다 |

지표는 세 조건 모두 같은 도구 안 AUROC(도구×출처 칸 9개, 칸의 위반 수로 가중)다. 조건 A·B는 데이터 나누기 3가지의 평균이다.

## 설정 6개 (실행 전 고정, 전부 보고)

| 번호 | 설정 | 같은 도구 안 학습 | 규제 | 랜덤 포레스트 |
|---|---|---|---|---|
| P1 | 최고 모델 그대로 | 없음 | 그대로(PCA 32·32·10차원) | 없음 |
| P2 | 같은 도구 안 학습 | 칸별 평균 빼기 + 칸 안 위반·정상 쌍 학습 | 그대로 | 없음 |
| P3 | 규제 완화 | 없음 | PCA 128·128·32차원, 벌점 1/10 | 없음 |
| P4 | 같은 도구 안 학습 + 규제 완화 | 있음 | 완화 | 없음 |
| P5 | 최고 모델 + 랜덤 포레스트 | 없음 | 그대로 | 넷째 구성원, 비중 1/4, 나무 500개, 잎 최소 10행 |
| P6 | 같은 도구 안 학습 + 규제 완화 + 랜덤 포레스트 | 있음 | 완화 | 위와 같음 |

- 조건 A의 P1·P2 값은 반복 14에서 이미 계산해 둔 점수를 다시 읽는다(새 학습 없음).
- **Argus-V-p로 정하는 규칙(실행 전 고정)**: 조건 B 값이 가장 높은 설정. 차이가 0.005 이내면 더 단순한 쪽(번호가 작은 쪽). 이렇게 고른 값은 같은 데이터에서 고른 것이라 낙관값이다.
- 조건 C가 0.9에 못 미치면 벌점을 한 단계 더 약하게(1/100), 그래도 못 미치면 PCA 512차원으로 한 번 더 맞춘다(최대 2회, 전부 보고).
- 고른 설정의 점검: 학습 라벨을 칸 안에서 섞어 조건 B를 다시 재면 0.5 근처여야 한다(누수 점검, 5회).

## 발표에 쓸 때

- 세 조건을 나란히 적는다. 조건 B·C의 수치를 "처음 보는 시나리오 성능"이나 판정 지표 값으로 적지 않는다.
- 평가에 들어가는 위반이 48개뿐이라 0.1보다 작은 차이는 구분되지 않는다.
- 0.90 목표의 대상은 2026-11-15에 사용자가 "행동 전에 근거가 보인 위반"으로 정했다. 그 구분 표시는 아직 없어서 이 문서의 수치는 평가 위반 전체 기준이다. 표시를 만들면 그 기준 값도 함께 적는다.

결과는 실행 뒤 `results.md`에 적는다.
