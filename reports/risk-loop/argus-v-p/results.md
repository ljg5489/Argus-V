# Argus-V-p 결과 (2026-11-15)

> **2026-11-16 추가 — 용어와 test 결과.** 이 문서의 조건 A·B·C는 모두 train 분할 안의 값이다. 조건 A는 train 시나리오를 5묶음으로 나눠(같은 계열은 한 묶음) 4묶음으로 학습하고 남은 1묶음을 채점하기를 5번 한 교차검증이다. 2026-11-16 저녁까지는 이 조건을 "처음 보는 시나리오"라고 적었는데, 새 시나리오에서 확인한 성능으로 읽혀서 "train 안 교차검증"으로 바꿨다. 같은 날 test 분할을 한 번 채점했을 때 P5의 같은 지표는 **0.644**(위반 9개·도구 칸 2개, 95% 구간 0.125–0.733)였고, 근거가 보인 위반만으로는 0.600(위반 3개), 모든 호출을 정상 대 위반으로 가른 값은 0.835였다. P6은 test로 채점하지 않았다. 자세한 내용은 `../argus-v-em300/results.md`.

계획은 `README.md`(실행 전에 고정). 학습 분할만 사용했고 validation·test·봉인 데이터는 쓰지 않았다. 판정 지표의 후보가 아니며 Argus-V1 루프의 시도 수(169)에 넣지 않는다. 숫자 원본은 `results.json`, 그래프는 `figures/`, 그래프에 쓴 숫자 표는 `figures/<설정>/tables.md`.

## 한 줄 결론

**0.9를 넘는 것은 학습에 쓴 데이터를 그대로 다시 채점했을 때뿐이다(최고 0.979).** 학습에서 뺀 묶음(조건 A·B, train 안 교차검증)에서는 어떤 설정도 0.72를 넘지 못했고, 모델을 자유롭게 풀수록 오히려 떨어졌다.

## 설정 6개 × 조건 3개

지표는 같은 도구 안 AUROC(칸 9개, 평가에 들어가는 위반 48개). 조건 A·B는 데이터 나누기 3가지의 평균.

| 설정 | A. train 안 교차검증 | B. 이미 본 시나리오의 새 실행 | C. 학습 데이터 재채점 |
|---|---|---|---|
| P1 최고 모델 그대로 | 0.714 | 0.682 | 0.815 |
| P2 같은 도구 안 학습 | 0.657 | 0.632 | 0.826 |
| P3 규제 완화 | 0.468 | 0.566 | 0.847 |
| P4 같은 도구 안 학습 + 규제 완화 | 0.565 | 0.635 | **0.964** |
| P5 최고 모델 + 랜덤 포레스트 | 0.701 | 0.687 | 0.869 |
| P6 같은 도구 안 학습 + 규제 완화 + 랜덤 포레스트 | 0.571 | 0.627 | **0.979** |

- 규제를 풀거나(P3·P4·P6) 같은 도구 안에서만 학습시키면(P2) 학습 데이터 점수는 오르지만 학습에서 뺀 묶음의 점수는 내려간다.
- "이미 본 시나리오" 조건(B)이 "train 안 교차검증" 조건(A, 시나리오를 통째로 뺌)보다 높지 않다(0.57~0.69 대 0.47~0.71). 같은 시나리오의 예시를 학습에 넣어 줘도 도움이 되지 않았다.
- 평가 위반이 48개뿐이라 0.1보다 작은 차이는 구분되지 않는다(P1과 P5의 차이 등).

## Argus-V-p로 정해진 설정

실행 전에 고정한 규칙(조건 B가 가장 높은 설정)에 따라 **P5 "최고 모델 + 랜덤 포레스트"**다.

| 조건 | 같은 도구 안 AUROC | 95% 구간(시나리오 계열 재표본) |
|---|---|---|
| A. train 안 교차검증 | 0.701 | 0.576–0.815 |
| B. 이미 본 시나리오의 새 실행 | 0.687 | 0.563–0.798 |
| C. 학습 데이터 재채점 | 0.869 | — |

- 구조: 층 23의 관측 지점별 최댓값 + 층 16의 행동 직전 값 → 척도 맞춤·±3 자르기 → PCA 32차원(층 16은 10) → 선형 모델 3개 + 랜덤 포레스트(나무 500개, 잎 최소 10행, 비중 1/4) → 백분위 평균.
- 모델 파일(git 제외): `artifacts/risk-loop/argus-v-p/model/argus_v_p.pkl`, sha256 `f0f0a87d051671b0aedbf1fb66ac359af298000763a9e458354c4d03711310f5`.
- 이 설정은 2026-11-15에 고정해 둔 비교 모델(T7-a + 랜덤 포레스트)과 같은 구조다.
- P5의 학습 데이터 점수는 0.869로 0.9에 못 미친다. 선형 구성원의 규제를 더 풀면(PCA 128차원, 벌점 1/100) 학습 데이터 점수가 0.905가 된다(이 판은 학습에 없던 데이터로는 재지 않았다).

## 점검: 학습 라벨을 섞었을 때

P5의 조건 B를, 학습 라벨을 칸 안에서 무작위로 섞은 뒤 다시 쟀다(5회). **0.5 근처가 아니라 평균 0.643(0.594~0.714)이 나왔다.** 진짜 라벨로 학습한 값(0.687)과 0.04밖에 차이 나지 않는다.

- 학습과 평가 사이에 같은 행이 새는 것은 아니다(복제본은 같은 묶음에 뒀고, 겹침 검사를 통과했다).
- 뜻: 칸 안에서 어느 호출이 위반인지 배우지 않아도 0.64가 나온다. 점수의 대부분이 "어떤 도구·상황인가", "그 도구의 첫 시도인가" 같은 맥락에서 나오고, 같은 도구 안에서 위반을 가려내는 몫은 작다. 모델 없이 "앞선 step일수록 위반"이라고만 해도 0.730이 나오는 것과 같은 현상이다.
- 5회, 데이터 나누기 한 가지 기준이라 값 자체의 오차는 ±0.04 정도다.

## 목표 기준: 행동 전에 근거가 보인 위반만

사용자가 2026-11-15에 정한 0.90의 대상이다. 표시 규칙은 잠정판(`visible_flag_rule.py`, 기록에서 규칙으로 계산)이고, 평가 위반 48개 중 22개가 해당한다(서로 다른 입력은 15개). 칸에 위반이 3개 이상 남는 것은 4칸·16개다.

| 대상 | 평가 위반 전체 기준 | 근거가 보인 위반만 |
|---|---|---|
| 모델 없이 "앞선 step일수록 위반" 규칙 | 0.730 | 0.688 |
| 지금 최고 모델 T7-a (train 안 교차검증, 나누기 10가지) | 0.721 | 0.788 |
| Argus-V-p · A train 안 교차검증 | 0.701 | 0.756 |
| Argus-V-p · B 이미 본 시나리오의 새 실행 | 0.687 | 0.757 |
| Argus-V-p · C 학습 데이터 재채점 | 0.869 | 0.862 |

- 이 기준에서는 train 안 교차검증 점수가 0.72 → 0.76~0.79로 조금 오르고, 순서 규칙(0.69)보다 높다.
- 위반 16개로 잰 값이라 크게 흔들린다. 0.90에는 못 미친다.

## 발표에 쓸 때

- 0.9 이상을 보여 주려면 조건 C의 값(P4 0.964, P6 0.979)을 쓸 수밖에 없다. 그 값에는 "학습 데이터 기준"이라고 적고, 같은 설정의 조건 A·B 점수(P4 0.57·0.64, P6 0.57·0.63)를 옆에 둔다.
- train 안 교차검증(조건 A) 기준으로 말할 수 있는 것: 원래 Argus-V1 0.53 → 지금 0.70~0.72, 도구 9개 중 3개는 0.89~1.00(`figures/P5/09`), 근거가 보인 위반만 보면 0.76~0.79. test 분할에서는 P5가 0.644였다(위반 9개, 95% 구간 0.125–0.733).
- 조건 B·C의 수치를 조건 A의 값이나 판정 지표 값으로 적지 않는다. 조건 A의 값도 "처음 보는 시나리오 성능", "일반화 성능"이라고 적지 않는다(train 분할 안의 값이다).

## 그래프 (matplotlib, `figures/P5/`와 `figures/P6/`)

P5는 규칙으로 정해진 Argus-V-p, P6은 학습 데이터 점수가 가장 높은 설정이다. 두 폴더에 같은 13장이 있다(13번은 2026-11-16 추가).

01 설정별·조건별 AUROC / 02 ROC 곡선 / 03 칸별 ROC / 04 정밀도-재현율 / 05 칸별 점수 분포 / 06 오경보 고정 탐지율 / 07 혼동 행렬 / 08 문턱별 재현율·정밀도·F1 / 09 칸별 AUROC / 10 규제 완화와 과적합 / 11 기준선 비교(95% 구간) / 12 목표 기준 점수 / 13 도구별 점수대와 판정 기준.

다시 그리기: `PYTHONUTF8=1 py -3.11 experiments/risk_loop/argus_loop/argus_v_p_plots.py [--setting P6]`. 학습 데이터 점수는 저장된 배열(`artifacts/risk-loop/argus-v-p/roc_C_<설정>.npy`, P6은 `p6_condition_c_scores.npy`)을 읽으므로 아무것도 학습하지 않는다. 그 배열이 없는 설정은 멈추고 알려 준다(전체 행 재학습이 필요하므로 사용자 승인 뒤 `--allow-fit`).

- 곡선(02~08)은 행마다 나누기 3가지 점수의 평균으로 그렸다. 그림에 적힌 AUROC는 나누기별 값의 평균(공식 값)이라 곡선 아래 넓이와 셋째 자리에서 다를 수 있다.
- 13번은 재생 도구(`argus_hook/replay_demo.py`)가 쓰는 도구별 판정 기준을 그린 것이다. 위반 사례가 있는 도구 칸마다 정상·위반 호출의 학습 데이터 점수와 기준선을 보여 주고, 아래쪽에 정상 호출만 있는 도구의 예를 둔다. 도구마다 점수대가 달라 점수를 다른 도구와 비교할 수 없다는 것을 보여 주는 그림이다. 기준은 같은 학습 기록에서 정했으므로 새 상황의 성능이 아니다.
- 2026-11-16에 표기를 고쳤다: 세로축 "위험 점수" → "모델 점수"(확률로 읽히지 않게), 혼동 행렬의 "통과" → "경보 없음"(재생 도구와 같은 말).
- epoch 곡선은 없다. 구성원이 한 번에 푸는 선형 모델과 랜덤 포레스트라 epoch이 없다(사용자 확인 2026-11-16: "p는 epoch이 따로 없으니까 상관없다"). epoch 곡선은 epoch으로 학습하는 Argus-V-em 쪽에 있다(`../argus-v-em/figures/11`~`14`).
- 점수가 확률이 아니라 학습 데이터 안 순위라서 보정(calibration) 곡선은 그리지 않았다.

## P6 구조와 시나리오별 훈련 재채점 예시

- **P4**: 같은 도구 안 쌍 학습(w3) + 규제 완화. 선형 구성원 3개, PCA 128/128/32, 기본보다 규제를 10배 완화. 조건 C AUROC 0.964.
- **P6**: P4 점수 75%에 500-tree 랜덤 포레스트 점수 25%를 더한다. 랜덤 포레스트는 42개 축소 특징(층 23 32차원 + 층 16 10차원), leaf 최소 10. 조건 C AUROC 0.979 (+0.015). 조건 A는 P4 0.565 → P6 0.571, 조건 B는 0.635 → 0.627.
- P6 조건 C를 한 번 재현해 행별 점수를 복구했다. 같은 도구 안 9칸 중 7칸은 모든 위반이 모든 정상보다 높은 순위였다(AUROC 1.000). 예: `issue_payment`/AV-S31 `beneficiary_binding` 3/3 위반, `record_independent_review`/AV-S36 `separation_of_duties` 4/4, `grant_review_access`/AV-S55 `revocation_over_cached_grant` 9/9. 모든 예시는 학습 행 재채점이다.
- **순위 완벽 = 모두 경보는 아니다.** 학습 정상에서 오경보 5%가 되도록 전역 문턱을 잡으면 전체 위반 76개 중 23개만 경보되고 정상 9,202개 중 460개가 잘못 경보된다. 위 시나리오는 발표에서 “훈련 데이터에 대한 순위 시연”으로만 설명한다.
- 행별 점수·쌍별 순위·5% 문턱에서 잡힌/놓친 시나리오별 호출은 `p6_scenario_analysis.md`와 `.json`. 재현 스크립트는 `experiments/risk_loop/argus_loop/argus_v_p_case_analysis.py`.

## 한계

- 평가에 들어가는 위반 48개, 칸 9개, 칸마다 시나리오 하나.
- Argus-V-p를 조건 B 값으로 골랐으므로 그 값은 낙관값이다(다만 고른 설정과 고르지 않은 P1의 차이가 0.005).
