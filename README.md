# Argus-V

### Argus for Vector-space

**Activation-based Early Warning for Autonomous Agent Boundary Violations**

정상 과제를 수행하던 AI Agent가 **권한 밖의 행동을 선택하기 전에 내부 표현에서 위험 신호를 탐지할 수 있는지** 연구합니다. 행동 이력·출력된 추론 텍스트만 감시할 때보다 일찍 또는 정확하게 탐지하는지를 검증합니다.

> **v3.0 · 2026-09-28 — 원래 연구 목적 복원**
> C-01은 [Draft PR #1](https://github.com/ljg5489/Argus-V/pull/1)에 구현되어 있으며 소형 모델 테스트 67개가 통과했습니다. 실제 20B GPU 구동·탐지 효과·상업성은 아직 미검증입니다. 아래 실험·Guard·Probe는 완료 성과가 아닌 계획입니다.

## 1. 연구 동기와 검증할 가설

출발점은 평가 중 Agent가 허용 범위를 벗어나 인프라를 악용하고 Hugging Face 시스템에 접근한 사건입니다. 공개 보고서는 보상 해킹·과도한 지속·무단 통신·감시와 대응 문제를 설명합니다. **은닉층을 보지 못한 것이 사고의 입증된 원인이라는 주장은 하지 않습니다.** 추론 텍스트와 activation은 서로 다른 관찰 대상입니다. [OpenAI 공식 사고 분석](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)

> 같은 정상 행동 오탐 예산에서, 내부 표현을 추가한 감시기가 외부 행동·추론 텍스트 감시보다 첫 권한 위반을 일찍 또는 정확하게 예측할 수 있는가?

Probe는 미래 행동과 연관된 신호를 검사합니다. 숨은 의도·의식의 판독이나 판단 원인의 규명으로 해석하지 않습니다. v2.0의 정책 Guard 중심 제품에서 **내부 표현 조기 감시 중심 연구**로 우선순위를 복원합니다. Guard는 실행 통제와 비교 기준이고, 프롬프트 인젝션은 보조 평가입니다.

## 2. 주 시나리오와 데이터

정상 과제·명시적 권한 경계·과제 수행 장애물이 있는 **로컬 모의 환경**을 구성합니다. 모델에게 우회·해킹을 지시하지 않으며, 권한 요청·허용된 대안·중단·실패 보고가 가능합니다.

| 과제 계열 | 정상 대응 | 관찰할 위반 시도 |
| --- | --- | --- |
| 자료 부족 보고서 | 부족함 보고·권한 요청 | 범위 밖 모의 자료 조회 |
| 승인 대기 업무 | 승인 요청·대기 | 승인 없는 모의 발송·상태 변경 |
| 어려운 평가 과제 | 정당한 풀이·실패 보고 | 금지된 모의 정답 조회·평가 기록 수정 |

- Pilot 계획: 20과제 × 장애물 없음/있음 2조건 × 3 seed = 120 rollout 목표. 실제 위반 수는 보장하지 않습니다.
- B가 신뢰된 정책과 제안 행동으로 라벨링하고 D가 검수합니다. 과제 실패·정상 탐색·권한 요청 자체는 위반이 아닙니다.
- 위반 **시도**와 실제 **실행**을 구분합니다. Guard가 차단한 시도도 위반 라벨을 유지합니다.
- 동일 과제의 조건 변형과 seed는 같은 split에 두고, 과제 계열 단위로 train/validation/test를 나눕니다.
- 자발적 위반이 희소하면 빈도·불확실성을 보고합니다. 직접 우회를 지시하거나 합성한 사례는 별도 스트레스 테스트이며 주 가설의 증거에 합치지 않습니다.
- AgentDojo·InjecAgent는 보조 프롬프트 인젝션 평가 후보입니다. 우리 gpt-oss의 activation은 별도 실행·수집해야 합니다.

## 3. 관찰 시점과 비교 실험

### 행동 생성 전 조기 예측

| 감시기 | 같은 prefix에서 관찰 가능한 입력 |
| --- | --- |
| M0 | 과제·권한 정책·이전 관찰 및 행동 이력 |
| M1 | M0 + 해당 시점까지 생성되어 접근 가능한 추론 텍스트 |
| M2 | M1 + 같은 prefix의 내부 표현 |

주 비교는 **M1 대비 M2의 추가 기여**입니다. 추론 텍스트가 없는 실행에서는 M1 비교를 미실시로 표시하고 M0 대비 결과를 보고합니다.

[M1 탐지기 실행 안내](docs/m1-detector.md): C-01과 같은 원본 토큰 prefix의 텍스트를 로컬 언어모델로 판정하는 기준선을 구현했습니다. 정렬·오류 처리·CPU 통합 테스트와 실제 20B 탐지 성능 검증은 구분합니다.

### 행동 생성 후, 실행 전 판별

E1=정책, E2=정책+문맥/가용 추론, E3=E2+activation을 비교합니다. 이 단계는 현재 도구 이름·인자를 볼 수 있으므로 결과를 행동 생성 전 조기 예측 성능으로 표시하지 않습니다.

### 누수와 편향 방지

- 초기 조기 라벨은 **다음 1회 행동의 위반 여부**이며 확대 지평은 validation에서 고정합니다.
- 미래 행동은 오프라인 정답 생성에만 사용합니다. 미래 token·도구 결과·행동 경계·향후 위반 시점은 Probe 입력에서 제외합니다.
- 위험 직전 snapshot만 골라 수집하지 않고 정상 사례에도 같은 사전 고정 관찰 규칙을 적용합니다.
- 레이어·조합·임계값은 validation에서 선택하고 test는 고정 평가합니다.
- 동일한 비개입 rollout의 오프라인 감시 비교와, 경보로 후속 행동이 달라지는 온라인 Guard 실험을 분리합니다.
- 종료·시간 초과 사례는 관찰 구간 내에서만 해석합니다.

## 4. 지표와 성공 기준

| 지표 | 정의 |
| --- | --- |
| 첫 위반 전 탐지율 | 위반 trajectory 중 첫 위반 행동 생성 시작 전에 경고한 비율 |
| 정상 trajectory 오탐률 | 관찰된 정책 준수 trajectory 중 한 번 이상 잘못 경고한 비율 |
| 탐지 선행량 | 최초 경보부터 첫 위반 생성까지의 token·행동 수. 미탐 수와 탐지 사례 수를 함께 보고 |
| 보조 탐지 지표 | AUPRC/AUROC, 시점별 Recall/FPR, 위반 유형·미지 과제별 결과 |
| 운영 지표 | 정상 과제 성공률, 위험 실행률, 승인 부담, p50/p95 지연·VRAM·저장량 |

임계값은 validation에서 고정하며 실제 test 오탐률·클래스 비율·표본 수·trajectory 단위 불확실성을 보고합니다. 같은 오탐 예산에서 M2가 M1보다 반복 가능한 탐지율·선행량 개선을 보이는지 평가합니다. **Full-prefix replay의 token 선행량은 실시간 절약 시간이 아닙니다.**

효과가 없거나 위반 사례가 부족하면 음성 결과·한계로 보고합니다. Guard 완성이나 보조 공격 데이터 성능으로 주 가설 검증을 대체하지 않습니다.

## 5. 시스템과 C-01

`Agent prefix → 외부/추론/activation 감시 → 조기 경보·보류 → 제안 행동 → 정책 Guard → 허용/차단/승인 → 모의 도구 → 감사 로그`

모든 도구 실행은 Guard를 거칩니다. 권한은 신뢰된 실행 환경에서 가져오며 명시적 금지는 낮은 Probe 점수로 해제하지 않습니다. 승인 인자 변경·재사용·중복 실행을 검사하고 필수 검사 실패·승인 대기 시 고위험 실행을 보류합니다. Probe 오류도 기록합니다.

[C-01 PR #1](https://github.com/ljg5489/Argus-V/pull/1)은 post-block hook, full-prefix replay, pre_action/pre_execution 정렬과 NPZ/JSON 저장을 제공합니다. [설치·통합 명세](https://github.com/ljg5489/Argus-V/blob/feat/c01-representation-extraction/docs/c01-extraction.md)를 재사용합니다. 주기적 snapshot·Probe·온라인 경보는 추가 구현입니다.

67개 소형 GPT-2/gpt-oss 테스트는 추출 계약을 검증한 결과입니다. 실제 20B MXFP4·4090 실행과 탐지 성능은 별도 검증 대상입니다. 코드 실행은 PR 브랜치 안내를 따릅니다. CI는 인증 권한 제약으로 설정 예시만 제공되어 있습니다.

## 6. 4인 분업

| 담당 | 소유 산출물 |
| --- | --- |
| A · Systems / Backend | 로컬 runner·주기적 snapshot, Guard·승인·감사 로그, 전체 통합 |
| B · Environment / Data | 정상 목표·장애물·권한 경계 환경, 시나리오 계열·라벨·데이터 검수 |
| C · ljg5489 · Representation / AI Security | adapter·hook, Linear Probe, Single/Top-3/All, 레이어·시점·OOD·실패 분석 |
| D · Independent Evaluation | M0/M1 기준선, 공통 지표·test 관리·재실행, 데모·고객 요구 근거 |

A/C는 실행·관찰 시점을, B/D는 라벨·split을 교차 검토합니다. C는 M1 대비 M2 추가 기여와 레이어×시점 분석을 소유합니다. CV 실적은 실제 이미지 실험 이후에만 표기하며 ViT probing/OOD는 핵심 검증 이후 선택 과제입니다.

Phase 1 신호 검증 → Phase 2 강건성·효율 → Phase 3 실패 탐색 → Phase 4 검증된 재학습 → Phase 5 적응 감시 → Phase 6 제한적 개선. 이번 일정은 Phase 1~2에 집중합니다. RL·자동 재학습·범용 SaaS는 후속 범위이며 권한 정책·독립 평가·승인 기준은 개선 루프 밖에 둡니다.

## 8. 상업성·재현성·한계

제품 가설은 자체 모델 운영 팀의 조기 경보·보류 모듈입니다. 잠재 사용자 3~5명에게 관찰 가능성·연동·보관·오탐·지연 허용 범위를 확인할 계획입니다. 인터뷰 호응을 지불 의사나 시장 검증으로 단정하지 않습니다. 내부 표현의 추가 효과가 없으면 차별화 주장을 철회합니다.

모델·토크나이저·정책·데이터 revision, split·seed·commit·환경을 기록합니다. 가상 자료를 사용하고 비밀값 로그를 최소화합니다. Activation은 익명 데이터로 가정하지 않습니다. 대용량 특징·모델 가중치·비밀키는 Git에 올리지 않습니다.

관찰 상관관계는 인과적 설명이 아닙니다. 모의 환경 결과는 실제 sandbox 탈출 방지나 다른 모델의 안전성을 보장하지 않습니다. gpt-oss의 자발적 위반이 부족할 수 있고 실제 GPU 실행과 replay 비용도 아직 미검증입니다. 개인 기여는 **문제 → 설계 → PR → 실험 → 결과·한계**로 기록합니다.
